## 1. 连接排查：分清上游和本机

对昨天已保存且 SHA 核验通过的公开 feed／反馈输入做五组传输诊断：首次 4 条输入与反馈后的 5 条输入，分别检查线程、localhost／IPv4 和代理环境。均返回正确维数，观察到向量范数约为 1；不是更换输入内容来掩盖失败。诊断保留输入摘要和连接事件，不记录请求密钥或认证头。

随后只运行推荐业务，不重复 PDF 检索／下载。真实 arXiv 首次请求发生超时，未取得 feed、未调用 BGE。这一轮标为失败，不能当成本机模型失败，也没有反复请求追绿。

## 2. 跨页名单：不再制造全局作者排名

官方 `2211.05100v4.pdf` 前三物理页有明确团体署名和职责分组。旧解析将团体、重复贡献者、跨行姓名残片混成 364 项作者列表，无法生成有完整来源的作者证据节点。

新规则只在标题之后、摘要／正文之前出现明确团体署名与贡献者标题时启用；最多检查前三页。角色标签直接来自原文，不按论文 ID 或预置人物名单生成。超过三页仍未见正文边界时，不将截断前缀声明为完整分组。

- 团体署名保留在 `authors`；新增 `contributor_groups` 保存原角色、转写成员和原文来源，不把不同贡献角色串成全局作者序号。
- 合并显式跨行／跨页姓名，区分行尾断词与姓名自身连字符；不猜测姓名重音、展开缩写或推断机构。
- 每个来源保留物理页、原始 block ID、bbox、原文。检索按每页原文分别建立贡献节点，不能把跨页完整名单抄到一个页码下作为证据。
- 原有作者节点、分组节点与普通正文分开。来源文本或几何不一致时整组不发布，避免用部分命中补出完整名单。

`ParsedDocument` 增加默认空字段，旧 AST 没有分组时不生成；正常解析版本提升至 layout104、OCR 至 ocr-layout99，使旧 checkpoint 不误当新元数据结果。没有自动迁移正式库的旧 AST、SQL 块或向量。

### 独立原文检查

使用 Poppler 和原生渲染检查完整物理第 1–3 页，而非裁剪名单。Poppler 输出两条 Symbol／ArialUnicode 字体回退告警，相关名单页仍可读；不据此声称所有特殊字形或全文都经过字体检查。

主要贡献者 35 项由原页独立转录后逐项比对；另外抽查 Prompt Engineering 跨页结尾、Applications 跨页姓名，以及行末断词／连字符。10 组共记录 553 项角色成员条目，**同一人可属于多组，553 不是独立作者人数，更不是全名单字符准确率**。未纠正的原文字层重音形式保留，带转写说明。

新旧解析的标题、73 页正文块、摘要、目录、表格、图、公式、参考文献和附录均比较一致；改变的是署名／分组结构与相应索引，不修改原始 PDF 或正文。

新临时库建立 424 个块。真实进程内 API 返回新结构，PDF Range 正常；词法检索分别取得团体署名、Prompt Engineering 第 2 页续名单和 Applications 第 3 页续名单的原文依据。来源与页码验证通过，但没有执行这些新字段的 BGE 稠密检索或 DeepSeek 最终回答验收。

## 3. 可复现入口与证据

正式入口已纳入项目：`backend/scripts/verify_official_grouped_contributors.py`，不是只在临时目录运行。示例在已安装项目依赖的 Python 环境执行，Windows 需令 PYTHONPATH 包含 `backend;backend/scripts`：

```powershell
python backend/scripts/verify_official_grouped_contributors.py --corpus-dir 科研小助手/pdf --output-dir backend/tmp/grouped-authors-new-run
```

必须使用指定 SHA 的官方 BLOOM v4 和完整 39 文件目录；输出必须是尚不存在的专用临时目录。可选 `--baseline-ast` 对照旧 AST；不提供时报告明确没有执行新旧结构比较，不默认为通过。
