# PaperPilot 演示录制脚本

技术内容核对版，2026-10-08，代码基线 `a26acbc`。目标 6 分 50 秒，普通话、中文字幕、H.264 MP4、1920×1080 或更高。

## 当前能录什么

本地实际地址为 `http://localhost:3300/`。文献阅读、引用图谱、Future Work 原文整理／待核验记录、CSV 图表和架构脚本已通过本地浏览器检查，可以先录这些镜头。不要隐藏本地录制的事实，也不要把本地地址说成公网在线演示。

问答、生成式综述、翻译和写作的正式镜头，等明确授权七篇公开论文摘录外发至 DeepSeek 并完成真实链路验收后再录。新七案例三轮没有成绩，不能口播成 21/21。历史五案例三轮成绩只能注明历史日期与范围。

公网部署完成后补录正式域名、门禁和外网业务验收，更新末尾地址卡；没有服务器和域名不妨碍先录已核验的本地操作。正式提交还需完整 MP4，不是交付此脚本就完成视频要求。

## 录制前清单

- 启动 Docker Desktop、PostgreSQL／Redis／Qdrant、后端、Worker、前端和两个 BGE 服务，等待健康检查。
- 关闭通知、个人书签和调试窗口，隐藏 API Key、账号和终端历史。
- 使用 100% 缩放、1920×1080；字幕距底边至少 80 px。
- 七篇固定公开论文已入库；需要长文档镜头时先导入真实 541 页教材并等待解析，不录等待全过程。
- 从 `docs/pdf-regression-corpus.json` 核对来源与 SHA。不要把自制扫描替代样本称作官方扫描原件。
- 版本上传需干净的演示库：先 v7 再 v1。不要为彩排删除有用文献；若两版已存在，展示实际差异记录并明确不是本次首次上传。
- 示例 CSV 数值为演示数据，不能标成 PaperPilot 实验成绩。字幕和图注均写清楚。
- 原文整理的核验记录只标待核验，不为演示随意确认研究问题已解决。

## 0:00-0:25　定位

画面：首页五工作区，依次指向文献问答、文献库、查找论文、研究脉络、研究产出。

解说：

> PaperPilot 用来管理论文、查找原文证据并整理研究材料。它把 PDF 阅读、问答、翻译、引用关系和制图放在同一工作区。重点不是答案写得多长，而是结论能否回到对应论文的具体页面。

## 0:25-0:55　架构

画面：技术文档架构图；突出 AST、检索、BGE 重排、DeepSeek、引用校验和原页定位。

解说：

> PDF 先解析为带页码、块编号和坐标的结构。检索和重排挑选相关证据，DeepSeek 负责组织回答，服务端再检查引用和数值。问答生成与证据整理是两条明确区分的路径，配置过模型并不代表某次调用已经成功。

## 0:55-1:40　上传与版本

画面：上传公开小样本；版本建议与修订差异；真实解析状态和结构。版本演示遵守录制前清单。

解说：

> 系统用内容哈希识别完全重复，再结合论文标识、题名和正文指纹识别版本候选。Transformer 旧版和新版不会因为文件名不同就重复当成无关论文。用户可以查看候选变化和原文位置，决定保留、替换或两版并存。公式字段是候选 LaTeX，并不是已经解决所有数学 OCR。

## 1:40-2:20　原文阅读与大文档

画面：点击“在线阅读”，展开三级目录；正文引用到参考条目，再返回正文。教材若未导入，用真实恢复验收记录代替页面镜头并注明。

解说：

> 阅读保留原始单双栏和页面版式。目录、引用条目和问答锚点共享解析坐标，可以跳回原页。真实 541 页教材已验证分批解析和中断恢复，这证明工程规模；它不等于教材每张表格都已正确抽取。

## 2:20-3:30　问答、比较与拒答（真实 API 验收后录）

画面：“文献问答”→“连续问答”，选择 Transformer，问优化器设置，点击原文引用；“多文对比”选择 GPT-1／2／3，提交参数量／上下文问题；最后选择 Transformer／BERT，问精确碳排放。

问题：

- `Transformer 的 Adam β1 和 β2 设置是什么？请给出原文页码。`
- `比较 GPT-1、GPT-2、GPT-3 的参数量和上下文长度演进，并逐项给出原文证据。`
- `比较 Transformer 与 BERT 训练产生的精确 kg CO₂e 排放量，并给出两篇论文报告的数值。`

解说：

> 每篇论文分别检索与重排，回答逐项附上原文。这里比较参数规模和上下文，不把模型背景知识当成论文报告。对于论文没有报告的精确排放，系统应说明证据不足。请注意，引用有效还不自动证明所有语义正确，我们仍保留金标和人工审校。

录制纪律：没有成功回答就暂停该镜头并处理，不能注入静态答案或用截图冒充当次模型结果。实际问题若超出固定金标，需先人工核验答案。

## 3:30-4:15　双语阅读（真实 API 验收后录）

画面：划选英文段落翻译；“中英”页级对照；左右分别拖动展示同步；关闭联动；展示整篇翻译状态和 Markdown／HTML 导出。

解说：

> 局部翻译和逐块对照保护公式、代码及引用。两侧可联动，也可独立阅读。整篇翻译后台逐页缓存，失败后可以续跑，输出 Markdown 或 HTML。当前没有原位双语 PDF 导出，整篇学术质量也仍需人工审稿。

## 4:15-5:10　发现、引用作用与未来方向

画面：“查找论文”展示实际搜索／已保存推荐；“文献库”→“下钻引用”展示书目匹配和正文作用；“研究脉络”→“引用图谱”→“证据综述”。原文整理勾选“仅整理原文（不调用 LLM）”，展开“记录人工核验”，选择待核验。

解说：

> 检索按题名和标识找到开放论文，推荐结合本地相关度、时间和代码信息。引用筛选把书目是否匹配与正文怎么使用分开，方法采用和基线优先，未知留给人工查看。图谱是当前文献库的局部网络。Future Work 就是作者提出的未来工作，系统寻找可能后续进展，但只有核对原文后才能记录人工判断。此处展示的是抽取式整理，不是模型生成综述。

若搜索源限流，展示已经保存的数据并说明是缓存结果，不伪称刚刚联网更新。确认已有解决证据镜头仅在真正完成研究核验时使用，否则保留待核验。

## 5:10-5:55　研究产出

画面：真实 API 验收后展示论文框架与来源书目；“架构图”→“整理四种脚本”；“数据作图”选择演示 CSV 和雷达／柱状／折线，展示 Caption 与脚本。

解说：

> 论文框架需要选定文献证据，书目由真实元数据重建，缺少字段会提示。图结构可以整理成四种可编辑脚本。CSV 工具检查数据并计算趋势，不编造显著性或因果。这里的 CSV 是合成演示数据，不能作为系统模型性能结果。
