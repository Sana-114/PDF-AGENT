## 已修复的四个具体问题

1. **名称缩写的数值误拦**：只有同一个被实际引用的摘录明确出现所有完整名称时，验证视图才展开 `Dataset-7/19` 这类带前缀的整数型号／数据集简写。不硬编码 CIFAR、论文名或正确答案，不改模型发布文本和原文。未引用的来源、不同摘录拼接、未知变体、普通分数与名称旁新增的 GPU／准确率仍受原数值规则检查。
2. **底层暂缓原因与原始预算不可见**：同一防护入口返回输入数量、通过数量、逐文献计数及带原索引的具体失败原因，经 harness、写作 API 到既有告警显示。兼容 `checked_claims` 包装不另跑一套校验；旧 API／旧输出没有审计字段也可读取。不把发布后的数量冒充原始输入数量。
3. **每篇简洁预算只提醒、不约束正文**：确定性分配先覆盖各篇，再允许各篇第二条，最多六条、每篇最多两条；跨文陈述占用各个实际引用文献的预算。预算外但通过基础来源校验的陈述保留为 `deferred_claims`，不删除、不自动改写、不计为科学失败；与真正防护失败分开。页面有折叠的补充事实、原页按钮，复制 Markdown 仅取框架正文和 References。所有有据原文本保留，两组各自维持原相对顺序；完整输入顺序仍由原调用记录留存。
4. **邻近段落借用了错误章节**：PDF AST 已正确识别 3.2，写作补邻近正文时却沿用 4 EXPERIMENTS。现在按实际块读取顺序归属标题；跨明确章节的邻居作为独立本地上下文，不伪装为未完句续页或独立重排命中。当前实际 E23／p4-b10 显示 `3.2 FINE-TUNING AND HIGHER RESOLUTION`、`context_for=[]`、本地上下文／0 分；原命中 ID、原文、bbox 及 AST 不变。

PDF 技能的完整原页核对将问题定位到写作证据组装，不是标题解析，所以没有重复重解析全部文献。流式解析／图形裁剪代码未改。没有新增第二套解析或写作驱动：扩展现有回放脚本支持保存的原始 claim 数组，并修复默认回放遗漏补充事实的问题。前端 Markdown 组装从组件提取为一个共用函数，避免复制与测试两套逻辑。

这些都是具体功能修复，不表示数值检查等同语义蕴含，或补充事实已经通过科学审稿。
