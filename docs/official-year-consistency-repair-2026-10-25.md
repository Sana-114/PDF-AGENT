# 写作与综述年份一致性修复

2026-10-25，接续当天录制环境续验。**修复已落在工作区，限定范围离线验证通过；未更新 Docker 镜像，未完成真实浏览器与生成复测。**

## 本轮修复

- 写作引用已有的会议首页页脚识别，原先没有接到综述时间线和 Future Work 后续论文的年份判断。现统一使用 `resolve_publication_year`：外部书目年份优先，其次有效 arXiv 标识，未知时才使用有位置与逐字摘录的首页出版页脚。不会用较晚会议年份替换已有预印本年份。
- 综述论文时间线新增可选 `metadata_evidence` 和“年份出处”按钮。年份来自页脚时，按钮携带同一文献 ID、页码、块及坐标；旧响应没有该字段仍兼容。出版信息不会进入模型的科学结论证据池。
- 统一逻辑也修复了综述读取非对象书目 JSON 时可能调用 `.get()` 报错的问题，拒绝将不完整 arXiv 标识、无效月份或长数字中的四位子串当成年份。保留未知值，不从文件名或参考文献猜测年份。
- 续验脚本原先把目录传给需要 JSON 文件的变量，现改为 `data/fixture.json`；检查 API、Worker 与工作区源码指纹一致后才继续运行验收，避免对旧镜像调用模型却宣称新修复通过。
- 浏览器脚本增加官方会议版 BERT 的年份与出处必填检查，以及综述时间线页脚跳转检查。这些新增步骤本轮仅通过语法检查，尚未真实执行。

## 实际验证结果

| 检查 | 结果 | 限定范围 |
| --- | --- | --- |
| 日期解析规则 | 12 项通过 | 原文页脚、日期优先级、无效格式、正文与参考文献排除、页码及冲突等；用标准库 unittest 执行 |
| 20 篇演示文献 | 通过 | SHA 固定 AST＋只读归档 Document 身份；18 个已有年份不变、1 个未知年份得到原页补全、1 个仍未知 |
| 前端回归 | 46 / 46 | 使用同进程 Node 测试模式；不是浏览器点击测试 |
| 前端类型 | 通过 | 新元数据字段和回调类型；初次类型检查发现多余 `evidence_kind` 参数，修正后通过 |
| Python／浏览器脚本／PowerShell 语法 | 通过 | 没有用语法检查代替后端集成测试或浏览器验收 |

首次 20 文件日期检查只读取 AST 中的 arXiv 字段，但多数文献的身份保存在 Document 表中；因此首份 `report.json` 只是 AST 单独输入的结果，不代表实际文献日期覆盖。最终使用当时恢复演示库的只读归档身份按内容 SHA 匹配，结果保存在 `report-with-document-identities.json`，两份均保留。

本轮没有新增独立论文问答，也没有调用 DeepSeek。此前 1,713 项后端全套通过属于修复前代码，**不能作为本轮修改后的全套回归成绩**。日期业务集成、真实 PostgreSQL、页面点击与模型生成仍待运行验证。
