## 实际发现并修复的问题

### 1. 删除后残留检索切块

首次删除官方 Transformer v1 测试副本时，文件、关联来源、Future Work 和本地向量已删除，但 SQLite 未启用外键，`document_chunks` 仍残留。不能仅靠数据库声明的 `ON DELETE CASCADE`。

统一删除流程现在显式清理目标文献切块。最终两种外键配置分别检查：目标 API 404、重复删除 404、PDF／AST／检查点／译文目录消失；切块、来源、方向核验记录及本地向量归零；另一篇 LoRA 的 API、文件、SQL 和向量保持；失效版本告警清除。普通删除、保留已有、替换已有三种移除路径另有 6 项外键开／关单测。

PDF／AST 是真实官方材料，检查点、外部来源与 Future Work 清理记录明确为合成附属数据。向量是**真实内存 Qdrant＋哈希嵌入，不是 BGE 或正式远程 Qdrant**。仅删除新建隔离副本，原件可重新复制；未清扫正式库历史孤立切块，也未证明文件／SQL／外部向量之间具备跨系统原子事务。

### 2. 缓存损坏仍导出“完成”的译文

使用已验收的官方 Transformer v1 15 页真实翻译缓存，先核对 PDF／AST 身份，再复制到新目录。首次故障注入发现：总页数为 0 或 1 仍导出成功，错误类型导致 500，文档／语言身份错配也可能被接受。首次失败全部保留。

修复后，完成状态的缓存页数须与可信原文页数一致；错误元数据以只读失败视图呈现，不能认证空篇／短篇完成。manifest 和页缓存分别校验文档、语言、页码与生成来源；缺字段也不当成已认证缓存。页正文、bbox、公式／代码保留等既有原文覆盖检查继续执行。

扩展 19 类故障包括总页数 0／少页／超大／布尔／错误类型、manifest 身份、缺页、错误 JSON、正文／坐标变化、受保护内容变化、页文档／语言／页号／模型／提供方错配及身份字段缺失。每次都记录状态、导出响应、只读操作前后的缓存哈希；随后恢复**测试副本的原始字节**，确认可再次正常导出。另用独立新 Python 进程读持久数据，状态和导出正常且未修改缓存，不冒充机器重启或外部 Worker 验收。

这关闭的是缓存完整性和导出恢复目标，**不是重新审校 15 页译文、重新翻译或浏览器联动验收**。恢复仅由测试工具显式执行，生产程序不悄悄修改缓存、补造翻译或自动发起模型重试。

### 3. 脚本返回正常，但图片有缺字／方向丢失

新增真实执行导出脚本的检查：中文分支、带引号／特殊字符、双向循环三种合成拓扑。初次运行缺 Matplotlib，使用已有本地验收依赖后确认中文成为方框；图片检查还发现固定端点缩短距离让箭头藏在节点下，双向边重叠，单看退出码和连线文本检测不出来。

现在 CSV 和架构图共用一个独立字体设置片段，从已安装字体中选择，API 本身不新增 Matplotlib 运行依赖；导出箭头从节点边界连接，双向及反向边使用弧线。最终三张完整图核对标题、文字、方向和循环；单测检查边界锚点与互逆连线。六组既有 CSV 同时复核实际折线／柱／雷达绘制值、缺失值、误差及图注，代表图片另行查看。

`requirements-plotting.txt` 记录此次使用的 Matplotlib 3.10.9，仅用于执行导出脚本。中文需系统安装相应字体。**Mermaid／DOT／TikZ 仅检查输出图关系，本机缺少 mmdc／Graphviz／XeLaTeX，未验证三者实际编译**；不把 Matplotlib 成功称为四种编译器全通过，也不宣称自动从论文推导出科学架构。
