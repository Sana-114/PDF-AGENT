# PaperPilot 作品介绍与技术文档

## 1. 项目概述

PaperPilot 是面向论文阅读与研究整理的科研助手。用户上传 PDF 后，可以在原始版式中阅读、对照译文、围绕选定文献提问，并沿引用关系整理后续阅读、研究方向和写作材料。

系统把回答与出处放在同一流程：解析得到页码、内容块与坐标，检索选择相关片段，模型组织陈述，引用校验检查来源，用户点击证据返回 PDF 原页。这样可以降低仅凭生成文本理解论文的风险，并保留复查路径。

### 本次提交内容

本文兼作作品介绍与技术文档，包含使用方式、六模块实现、架构与 AI 技术、测试、部署和创新说明。配套视频约 6 分 24 秒，1920×1080，普通话合成配音与中文字幕；源码提供环境模板、依赖清单、测试和启动脚本。

仓库：https://github.com/Sana-114/PDF-AGENT 。业务代码基线为 f8d73dd；完整提交材料对应的 Git 提交及文件校验值以包内 VERSION.json、SHA256SUMS.txt 为准。Git 历史保留在远端仓库，源码 ZIP 是便于评审下载的同版本子集。

### 预指导后的改进

预指导得分 86 分，反馈认可代码、测试用例和视频，并建议优化翻译后的中英对照阅读。本轮重点改为按原文块对应定位，扩大双语阅读区域，补充实际上传、跨文比较、论文框架和联网检索镜头，配音改为整段神经语音合成。

### 项目来源与经历

根据项目方确认，本项目此前未发表、未参加其他比赛、未获奖，不是基于某个现成项目改造。系统使用开源框架、预训练模型和第三方 API；创新集中在科研任务组织、证据约束、阅读联动与可复核流程，不声称基础模型或第三方框架为自行训练或开发。

## 2. 使用方式与需求对应

运行后，先在“文献库”上传单篇或批量 PDF，等待解析完成。选定论文后进入问答或多文对比，点击每条陈述旁的证据按钮核对原页。阅读器支持目录、引用往返和对照译文；“研究脉络”整理图谱与综述，“研究产出”生成框架、翻译和图表。

| 比赛模块 | 主要功能入口与实现 |
| --- | --- |
| 文件与解析 | PDF 上传、状态、删除；内容指纹、版本建议；原生文本、OCR、结构节点与分批解析 |
| 知识问答 | 选定文献检索、BGE 重排、DeepSeek 生成、逐声明出处及证据不足提示 |
| 阅读翻译 | 原生 PDF 渲染、目录、引用往返、局部翻译、段落对照、全文 Markdown／HTML 导出 |
| 检索推荐 | 题名／DOI／arXiv ID 检索与导入、引用下钻、订阅、代码链接加分和点赞／踩 |
| 图谱综述 | 库内有向引用图、局部 PageRank、证据综述、Future Work 与后续原文核对 |
| 写作可视化 | 三节论文框架、真实书目、四类架构脚本、CSV 图表与图注、中英学术翻译 |

### 推荐体验路径

1. 上传公开论文，打开原文，尝试目录和参考文献跳转。
2. 开启中英对照，点击译文的“定位原文”，查看高亮；调整字号，再从英文点击回到译文。
3. 选两篇相关论文提出比较问题，分别检查它们的证据来源。
4. 根据已有材料生成写作框架，复制带引用的 Markdown；上传 CSV，切换图形并导出。

原位排版 PDF 翻译不是当前交付格式；已提供的 Markdown／HTML 是赛题列出的允许输出方式。多用户协同推荐属于后续扩展，不能把当前共享反馈排序表述为已实现多用户隔离。

## 3. 系统架构与 AI 技术选型

| 层次 | 组件 | 职责 |
| --- | --- | --- |
| 交互层 | Next.js、React、PDF.js | 工作区、原始 PDF、证据定位、对照阅读和可视化 |
| 服务层 | FastAPI、Agent Harness、任务技能 | 请求校验、文献范围、检索与生成编排、结果审计 |
| 异步层 | Celery、Redis、Beat | 解析、全文翻译、进度恢复和订阅刷新 |
| 数据层 | PostgreSQL、文件卷、Qdrant | 文献状态、Document AST、原件与向量索引 |
| 模型层 | BGE-M3、BGE Reranker、DeepSeek Flash | 语义召回、候选重排和基于证据的生成 |

### 核心数据流

PDF → 文件校验／内容身份 → 逐页解析 AST → 切块／索引 → 召回与重排 → 证据池 → 模型陈述 → 来源与数值检查 → 前端回答及原页跳转。

BGE-M3 用于补充词项匹配难以覆盖的语义表达；词项检索保留专有名词和参数符号的召回能力。重排模型再评价候选与问题的关联度，减少无关段落进入生成上下文。DeepSeek 用于问答、综述、写作和翻译的语言组织，不负责虚构缺失书目或实验值。

### 编排与优化

Harness 将检索、证据检查、生成和校审组织为可追踪步骤。技能是项目中的任务处理单元，不是仅靠提示词命名的菜单。多文任务按论文分配证据预算，避免长文档占满上下文；写作可扩展邻接段落以保留跨页条件；全文翻译逐页缓存并记录失败状态。

抽取式整理与生成式结果分别标注。BGE 服务或外部模型不可用时保留降级信息，不能把回退结果记为真实模型验收成功。图表统计和书目格式化采用确定性程序，减少无需模型参与的步骤。

## 4. PDF 解析与中英对照阅读

Document AST 保存标题、作者、机构、摘要、层级标题、表格、图像区域、公式候选、参考文献与附录等结构信息，并关联页码、块编号和 bbox。原生文本优先使用版式信息；低文本页进入 OCR；长文按批次写入检查点，避免一次将整本书载入模型上下文。

内容管理先做文件 SHA-256 完全去重，再进行正文相似度和版本判断。文件名不同不会直接视为不同作品；检测到可能重复时显示保留、替换或并存等选择，并提供可核对的差异信息。

![图 1：改进后的摘要对照。译文定位到左侧原文块，原文区域高亮。](docs/assets/bilingual-20261110.png)

### 本轮阅读改进

原实现按两侧滚动百分比联动，译文长度变化会导致内容错位。现在依据译文块编号与原文坐标定位：译文按钮跳转原文并高亮，原文块点击找到译文；滚动按邻近内容块匹配。双栏页面使用已选中的栏约束原文侧匹配，不能将纯纵向位置当作完整阅读顺序。

开启双语会收起目录，PDF 适应可用栏宽；译文默认 16px，可调整到 14／18／20px。没有可靠坐标的块保留原文文字查看入口，不伪造位置。公式、代码、数字和引用标记通过受保护片段参与翻译完整性检查。

## 5. 证据问答与跨论文推理

单篇问题从选定文献中检索，输出由声明、证据 ID 和原页定位组成。多篇比较分别召回原论文，以每篇自己的正文支持机制或实验事实，避免把参考文献列表当作本文贡献，也避免用一篇论文的证据替代另一篇。

生成后检查引用是否在证据池内，数值是否有来源，比较是否覆盖相关原文，以及特定实验条件是否遗漏。对可明确识别的关系和范围冲突采用规则或独立模型校审；检查的覆盖范围有限，引用存在本身不等于科学结论完全正确。

![图 2：真实跨论文比较的来源核对镜头。](docs/assets/formal-comparison-20261110.png)

### 验证和修复实例

真实 BERT／Transformer 对比解释了双向 encoder 与原始 encoder-decoder 架构的关系，并分别打开两篇原文。LoRA／QLoRA 写作验收检查共享的冻结权重／低秩适配机制，以及量化与分页优化器的区别。

一轮写作曾把 more than 1,000 models 写成“少于 1,000 个模型”。失败结果保留，增加相同模型数量单位下的明确上下界反向检查，重新生成后的样稿核对通过。这项检查只覆盖有明确数量和单位的限定场景，不宣称实现通用事实证明。

## 6. 发现、引用图谱与研究产出

论文发现通过学术索引按题名、DOI 或 arXiv 标识匹配候选。导入端重新核对来源地址、跳转、大小与 PDF 内容，保存来源元数据，并复用入库校验。订阅按关键词或分类刷新，推荐考虑本地文献相关度、新鲜度和开源代码线索；引用用途筛选保留上下文依据。

图谱只描述所选文献范围内的关系。入度和 PageRank 辅助标记基础、桥接与边缘节点，不能据局部排名宣称全领域影响力。综述与未来方向带原文证据：后续工作能支持明确目标已完成时，将其移出开放推荐；部分进展继续保留，并允许人工复核。

![图 3：局域引用关系及所选论文信息。](docs/assets/formal-graph-20261110.jpg)

写作框架分别接收研究主题与写作要求，避免把操作指令写进摘要。Abstract、Introduction、Related Work 使用已核验陈述；References 从实际文献元数据构造，缺失字段不猜测。

CSV 工作台按原始数据计算统计摘要，生成折线、柱状和雷达图，图注描述可核验的数值趋势。架构图从模块连接生成 Mermaid、Graphviz、TikZ 和 Matplotlib 脚本；图形输出可继续编辑。学术翻译支持术语表、段落保留、人工修订及 Markdown 导出。

### 测试方法

离线回归覆盖请求校验、解析恢复、引用范围、数值防护、缓存和删除清理。真实模型验收明确记录模型、选定论文、证据及回退状态；浏览器检查要求 PDF 实际绘制、控件响应和下载文件，不仅检查元素存在。失败不会被新结果覆盖。

仍需关注复杂扫描公式、扫描与矢量版本识别、部分引用作用判断、多用户隔离，以及未抽查版式的双语定位。优先改进有原文对照的具体失败，避免反复修改测试题以制造通过结果。

## 8. 安装部署、创新与后续工作

### 安装与运行

运行环境使用 Docker Compose；标准模式包括数据库、任务队列、Qdrant、BGE 召回和重排服务。第一次运行需下载镜像和模型，并根据机器内存、磁盘与 GPU 情况配置。源码包不包含模型权重、真实密钥、官方 PDF 或既有数据库。

复制 .env.example 为 .env、.env.bge.example 为 .env.bge。设置 LLM_PROVIDER=deepseek、LLM_MODEL=deepseek-flash、LLM_BASE_URL=https://api.deepseek.com，并通过自己的环境变量填入 LLM_API_KEY。模板默认 mock，不应将其当作真实生成模型。执行 pwsh -File scripts/start.ps1 -Mode standard，再通过 scripts/status.ps1 检查服务。默认前端端口 3000，实际以配置为准。

OCR 宿主机测试需安装 Tesseract 及相应语言包并设置 TESSDATA_PREFIX。后端安装 requirements.txt、requirements-dev.txt 后运行 pytest；前端运行 npm ci、npm test 和 npm run typecheck。模型及浏览器集成测试还需启动服务并导入公开样本。

### 部署状态

公网代理、环境模板与部署脚本已保留，正式公网服务器、域名、地址与评审账号尚未完成。最近隔离录制使用已有镜像同步源码；基础镜像源曾返回 401，因此不能把该次录制当作干净服务器重建成功。上线前需验证镜像获取、模型健康、上传解析、生成、外部访问和备份恢复。

### 技术与应用创新

技术上，以同一文档块身份贯通解析、检索、回答、双语定位和导出；采用逐声明引用检查、多文证据预算及条件保留，降低无依据结论进入正文的概率。应用上，把“读译文、核对原文、比较文献、形成材料”连接起来，并保留人工审校入口。

后续工作重点是增加版式覆盖、提高复杂公式恢复质量、验证更多研究判断及完善多用户推荐。现阶段优先保证可追溯与可复查，而非宣称消除所有模型幻觉。项目将以固定源码版本、明确样本范围和真实操作视频提供评审依据。
