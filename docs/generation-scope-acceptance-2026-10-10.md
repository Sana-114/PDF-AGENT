# 第 84 阶段：明确生成文献范围

日期：2026-10-10。解决综述、写作默认使用全库而可能误外发无关或私有论文的问题。

## 实现与实际结果

- 综述和写作增加折叠式文献范围选择；不预选文献，空范围按钮禁用，只提交显式勾选且已解析的 ID。已移除或未就绪的文献不进入请求。
- 生成式综述接口拒绝空／缺省范围；写作框架要求非空文献列表。抽取式本地综述仍可无范围使用全库，不调用外部模型。
- 浏览器验收脚本只允许两篇 SHA 固定的公开论文，每个生成接口最多提交一次。合成翻译输入也固定；不替换 API 响应，不注入保存的模型答案。
- 原本地录制检查适配新选择控件，抽取式综述只勾选公开测试语料。

全量后端 **302 项**、前端 **29 项**测试通过，Ruff、类型检查与 Docker 前端生产构建通过。1920×1080 Edge 真实页面检查空范围禁用、两篇公开论文勾选，结果通过；该运行没有 `--allow-cloud`，生成请求计数为零。

机器报告：忽略的 `backend/tmp/stage84-scope/browser-scope-2026-10-10.json`。没有发送本地用户论文、删除文献或数据卷，没有改变公网配置。

## 复现

标准模式运行后，从 `frontend/` 执行：

```powershell
node e2e/generationReadiness.mjs --output ../backend/tmp/generation-readiness/scope.json
```

必须另获授权才能增加 `--allow-cloud`；那是新的真实模型调用，会产生费用，而不是读取旧回答。本阶段仅证明范围控件可用，不证明生成质量。下一阶段仅执行用户授权的三类小样本。
