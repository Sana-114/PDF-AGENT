## 问答复核与修复

三题的 PDF、原题、数值金标不变，使用只读隔离索引，不重解析、不回写向量。Pre-LN 的正文第 2／5 页正确解释位置，机器原金标要求首页摘录；GPT-1 两阶段与输入适配正确，但没有匹配固定中文短语。扫描 Adam 则通过机器检查。两个失败原记录保留；另以 [三题复核政策](../backend/evals/official_runtime_three_review.json) 绑定报告 SHA、原文件 SHA、已发布陈述、证据 ID 与实际物理页。

修复希腊变量下标被当成额外数值的误拦，未改写 OCR 正文、未在生产规则填入 Adam 答案。生成提示减少重复回答占用；响应未完成时即使部分 JSON 可解析也不能发布，保存供应方状态与诊断。截断仍可能发生，不宣称已永久消除。

随后对原九题作一次同候选确认：作者／机构、Adam、GPU、BLEU、指定引用、BERT 架构对照、GPT 参数、LN 变化、上下文演进均通过。使用原来的五份公开文件，BGE-M3 稠密向量＋现有稀疏混合召回＋BGE Reranker，实际证据均经过混合召回与重排。GPT-1 参数和窗口明确区分后出论文基线识别推断与直接报告，BLEU 差值明确为同表同任务计算。完整复核记录见 [九题政策](../backend/evals/official_runtime_nine_review.json)。未做下一轮三个高风险题的有限稳定性确认或新云端反例。

本轮新增 DeepSeek 调用 **13 次**：三题 3、原九题 9、正式 API 冒烟 1。两个索引预检失败均为 0 次生成。没有自动重试模型，不发送私有论文；其他浏览器／缓存检查调用模型 0 次。10 月 12 日的写作调用不计入此数字。

## 运行镜像与已有数据是两件事

后端、worker、beat 的 119 个 `app/*.py` 文件摘要与主机一致：`cf0ffab4624cb96dca83d4b395072d45a7d390741327c522e01fff9f9fc456f8`。依赖清单未改变，本轮利用已有镜像依赖更新代码，没有重新下载模型；这不是干净机器安装验收。容器 Python 3.11.17，主机离线回归 Python 3.12.14。

前端已完成真实生产构建并更新运行镜像。PostgreSQL、Redis、Qdrant、MinIO 设置 `unless-stopped`；构建时临时停止的两个 BGE 容器已恢复健康。升级前数据库备份与四个旧镜像标签均保留，不删除卷。正式文献库仍是 8 份文件；三个临时验收服务完成后停止，结果文件保留。

正式 API 冒烟只选择 SHA 与官方 Transformer v1 完全相同的一份文件，没有发送全库。其已入库解析版本仍为 `1.26.4`。第 2 页引言续段的块前被旧解析插入了 `3.1 Encoder and Decoder Stacks`；模型沿用该标签，所以附加句的章节不正确，而 GPU 数值、型号、时间及物理页正确。它不是最新 layout98 隔离数据的失败，也不是可以忽略的“全通过”。

本轮**没有自动重解析正式库**，避免直接替换历史 AST／索引及影响旧引用锚点。下一步应对这份已确认公开的旧记录先备份，再重解析和刷新索引，明确历史引用变化；其他私有文献不在本次处理范围内。

## 版本选择与浏览器隔离

在新建空库里，将官方 v7／v1 改成不含 arXiv 版本的上传名称，真实上传、解析，再点击界面选择。PDF 正文识别出 v7／v1；冲突评分 0.8481，差异正文重合 0.6623。保留操作只移除测试副本 v1，替换只移除测试副本 v7；官方原件和正式库未删除。另验收两版并存和同内容改名上传不再插入。

浏览器使用真实前端 `localhost:3300` 与实际隔离 Docker API，不伪造响应体；这是运行组件验收，不声称正式库完成上传→异步 worker→所有生成业务的一次全闭环。版本测试专用 Celery 为 eager＋内存 broker／cache 结果后端，正式 Redis／worker 配置未改变。
