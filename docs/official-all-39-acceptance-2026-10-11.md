## 3. 本轮修复及未确认效果

1. **扫描作者脚注噪声**：官方扫描姓名尾部 `*|` 导致精确名单失败。仅在已有署名脚注后去除附着竖线，保留原 OCR 文本；不清洗姓名内部或裸竖线。当前解析器版本为 `layout97`，扫描八位作者的基础检查通过。四个表格候选不代表每个单元格已验收。
2. **旧索引与当前 AST 漂移**：生成前逐块校验页、章节、文本、block IDs 和 bbox。BERT 旧索引与当前 AST 不一致，首次准备保留失败且模型调用为 0；只在新隔离集合重建当前 AST。最终 35 份只读复用、1 份漂移重建、3 份新增全文索引（v7、扫描、教材），不覆盖旧集合或生产库。
3. **参数括号别名误拒**：识别数量相等的有限括号赋值表达，仍要求参数标签和同源证据；不把训练 token 或计算量当参数。
4. **万亿／trillion 数值误拒**：支持 `trillion`／`T` 与中文万亿的通用 Decimal 归一化。没有硬编码 Qwen 数值；错误量级、百分比、无效引用和不匹配数值仍拒绝。保存输出回放恢复 Qwen 两条声明，但真实运行中的空回答成绩不改写。
5. **明确机制拒答漏标**：对于“为什么”问题，回答明确表示证据未提供原因／机制时标为不完整，并记录 trace；保留已支持的部分结论，不用规则生成机制。PPO 当前回放维持不完整。
6. **回答范围提示**：要求仅回答所问字段、避免无关模型与“资料缺失”补充、限定模型变体及训练阶段。调整后的提示尚未获得新生成确认；旧输出回放不能证明新提示有效。

现有引用及数值防护不是通用语义蕴含验证器。它们不能单靠“引用存在”判断所有定性结论正确，也不能替代完整原页审查。

### PPO 的第二层原因：摘要找到不等于机制找到

进一步查看 PPO 完整物理第 3 页发现，原请求只有摘要中的多轮更新和悲观目标说明，没有正文中“裁剪去除继续越界改善目标的激励”的段落。新增通用机制召回：对“为什么／原因／工作原理”等问题，从同一范围的现有块中有限召回因果说明，并经过真实重排、原分数门槛和有界选择。不添加论文专属答案、指定答案页或数值。

重排只在打分输入中加入各块已有的真实论文标题与章节标题，每字段最多 160 字符，字节批次预算也计入这些文本；原 quote、block IDs 和 bbox 不改写。机制问题的重排查询明确表达机制意图，其他问题与引用题保持原查询。最终正文第 3 页进入实际可用证据，得分 **0.1864**，原门槛仍为 **0.18**；它还不是新生成正确结论或稳定性证明。

最初机制诊断漏查分数过滤，候选命中被误记为通过，原结果保留且不用于放行。修正工具后第 2–5 次本地诊断仍失败，均保留；第 6 次实际可用证据的 6 个来源检查通过。这里只调用本机 BGE，未增加 DeepSeek 调用。随后重新执行全部 39 道原单文件查询，固定原问题、来源与 AST，确认各自独立依据均进入最终可用预算。

这轮首份全候选锚点检查为 38/39：扫描件存在一个低于门槛、没有发给生成器的无效候选锚点。最终检查明确对应生产 Harness 实际使用的证据，得到 39/39，同时单独保留该候选异常。两项检查范围不同，不能描述成修复了所有候选或把旧失败删掉。扫描 OCR 表格及噪声候选仍有质量边界。

## 4. 长文档与运行边界

541 页教材以每批 25 页执行，50 页后中断并恢复，最终 22 个 checkpoint 批次齐全。首个恢复进度回调为第 75 页。最终总耗时 **65.964 秒**，Python 分配峰值 **11.01 MiB**；Windows 进程 RSS 未采集，记录为 `null`，不是 0，也不能当作服务器总内存或 GPU 显存需求。

标题树、图、公式与参考文献数量为解析候选节点数，未逐项打准确率；教材表格候选为 0，仍需代表表格人工抽查。v7→v1 的正文 bottom-k 指纹重合为 60%，结合正文 arXiv 身份进行重复建议；这不是 BGE 语义等价分数。

本轮使用主机工作区的生产 `ResearchAgent.ask`、真实 BGE-M3 稠密向量、现有哈希稀疏／BM25 混合检索、BGE Reranker 与 `deepseek-flash`。不是 BGE 学习型稀疏向量。临时 SQLite／Qdrant 集合隔离，旧失败集合保留。没有重建 Docker 镜像、更新前端或重新做浏览器验收，不能声称 localhost 界面已经运行这些修复。
