# 多文 RAG 证据审计与对照矩阵验收（第 61 阶段）

## 本阶段目标

在已有“每篇论文独立召回”的跨论文对比链路上，继续处理三类风险：重复段落挤占上下文、模型自由总述绕过 Claim 校验，以及结论虽有引用但难以快速核对各论文原文。

本阶段完成：

- 每篇论文先召回最多 `3 × evidence_per_document` 条强候选，再按页码、章节、证据类型和文本相似度选择固定配额；
- 所有模型 Claim 必须只引用本轮 Evidence 白名单，混入未知 Evidence ID 的整条 Claim 会被拒绝；
- 一致、差异和冲突 Claim 必须引用至少两篇论文，否则降级为单来源；
- Claim 内出现的数字、百分比、年份、参数量或指标值必须在所引原文中精确出现；`175B` 与 `175 billion` 可归一匹配，但 `312` 不会错误支撑 `12`；
- 不再直接发布 LLM 的自由文本 `answer`，最终回答只由通过校验的 Claim 和 Evidence ID 重建；
- API 返回对比维度、逐论文证据矩阵和审计指标；前端可从每个矩阵单元格跳回对应 PDF 页；
- 若两篇以上论文虽有检索证据但没有形成任何跨文献 Claim，结果明确标为证据不足。

## 自动化覆盖

`backend/tests/test_paper_comparison.py` 覆盖以下场景：

1. 两篇论文等额独立召回、全局证据编号和关系分类；
2. 只有一篇论文命中时拒绝生成跨文献结论；
3. 原始 LLM 总述包含未证实数值时不会进入发布答案；
4. Claim 中未被原文支撑的数值会被拒绝并写入审计原因；
5. Claim 混入未知 Evidence ID 时整条拒绝，不允许用剩余合法引用蒙混通过；
6. 重复 Chunk 去重后优先保留跨页、表格与公式证据；
7. 数字采用完整事实 token 匹配，避免子串误判；
8. API 拒绝重复文献 ID，并返回来源感知的 Claim、矩阵和审计字段。

## 真实解析语料烟测

使用第 60 阶段已经真实解析的 ResNet、ViT 和 DDPM 三篇论文，通过内存数据库从真实 Document AST 重建正文/结构 Chunk，并使用确定性 BM25 基线执行同一多文问题。该烟测不调用外部 LLM，也不读取 API Key；Provider 只生成固定 Claim，用于验证检索、证据选择、审计与发布门禁的组合链路。

结果：

- 三篇论文均从 12 条强候选中保留 4 条证据，共 12 条；
- 每篇入选证据均覆盖 4 个不同页面；ViT 结果还同时包含正文与表格证据；
- 1 条跨文献 Claim 引用 3 篇论文并通过白名单，矩阵生成 1 行；
- 自由总述中故意放入的未证实数字 `999` 没有进入发布答案；
- 审计记录引用覆盖率 100%、跨文献 Claim 1 条、被引用文献 3 篇；
- 机器报告保存在忽略目录 `backend/tmp/stage61-multidoc-smoke.json`。

## 输出契约

跨论文接口 `POST /api/v1/agent/compare` 新增：

- `papers[].candidate_count / evidence_page_count / source_types`：每篇候选量与证据多样性；
- `claims[].dimension`：LLM 给出的对比维度，缺失时由证据章节保守补全；
- `matrix[]`：每条结论在各论文中的实际引用、原文摘要及 Evidence ID；
- `audit`：生成、接受、拒绝声明数，引用覆盖率、证据利用率、跨文献结论数和拒绝原因。

新增字段都有服务端默认值，但同仓库前端已同步升级类型与展示，不依赖浏览器自行推断。

## 已知边界

- 当前数值门禁证明“数值出现在所引证据集合中”，尚未把复合句拆成主语—数值—单位三元组，因此仍需通过矩阵核对归属关系；
- 一致、差异和冲突标签由 LLM 提议，服务端能校验来源数量，不能形式化证明自然语言逻辑矛盾；
- 没有数字的新事实主要依赖 Evidence ID、原文引用和人工跳转复核，后续可增加 NLI/事实蕴含模型作为可选门禁；
- 候选多样化使用确定性启发式，不替代 BGE-M3 与 Cross-Encoder 的语义召回、重排能力。
