## 本轮发现并修复的问题

1. OCR 将页边 arXiv 标识、作者网格和正文合并为大块，最大字号不再能代表整个块。解析器现在使用按字符加权的字号中位数，避免单个大字污染正文和目录阈值。
2. OCR 可能把首页 Abstract 识别为 `5 Abstract` 且估算字号大于论文标题。标题候选现在排除已知和编号章节标题。
3. 多栏作者区可能合并成单个 OCR 块。解析器会利用姓名后的脚注星号恢复作者列表，最终得到与矢量版一致的 8 位作者及顺序。
4. OCR 中真实章节标题的估算字号可能低于正文。格式明确、长度受限且不以句号结尾的编号标题不再依赖字号阈值，目录节点由 6 个提升到 23 个。
5. 解析评测器新增作者数和 OCR 页数指标；扫描样本清单进一步约束至少 20 个目录节点、30 条参考文献、180 秒耗时和 256 MB Python 峰值内存。

## 当前边界

- Tesseract 会产生少量字符级错误，例如把 `5.1` 识别为 `§.1`；当前不基于上下文擅自修改 OCR 原文。
- 纯栅格扫描页被识别为整页图像，当前基线不会伪造表格单元格或独立图区域。扫描表格结构和图像区域需要接入版面检测/表格识别适配器。
- 公式结果是带坐标的文本候选，不代表 LaTeX 无损反演。
- 收到组委会原始扫描文件后，必须用同一清单重新验收，不能用本替代样本成绩代替官方结果。

## 可复现命令

```powershell
docker compose exec -T backend python scripts/build_pdf_fixtures.py `
  /app/tmp/stage40/1706.03762v1.pdf `
  /app/tmp/stage40 `
  --scan-pages 15 `
  --scan-dpi 144 `
  --scan-filename 1706.03762v1_img.pdf `
  --only scan

docker compose exec -T backend python scripts/evaluate_pdf_corpus.py `
  /app/tmp/stage40/corpus `
  --manifest /app/tmp/stage40/manifest.json `
  --output /app/tmp/stage40/ocr-report.json `
  --batch-pages 3 `
  --strict
```
