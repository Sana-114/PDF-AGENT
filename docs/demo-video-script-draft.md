# PaperPilot 比赛演示视频脚本初稿

> 目标时长：6 分 55 秒  
> 输出规格：MP4、1920×1080 或更高、普通话讲解、中文字幕  
> 录制版本：最终公网部署版本  
> 当前状态：脚本与镜头初稿；在线地址、团队片头和最终测试数字待提交前替换

## 1. 录制原则

- 只演示已经通过验收的主链路，不在视频中等待模型下载或 541 页完整解析。
- 预先入库七篇公开论文和长文档；现场上传只使用 Transformer v7/v1 小样本。
- 所有答案至少展示一次原文页码、引用按钮和 PDF 高亮。
- 必须展示一次证据不足拒答，证明系统不是“每问必答”。
- 测试数字只使用仓库验收记录中的结果，不把固定样本成绩描述成通用准确率。
- 录制前隐藏浏览器书签、个人 GitHub 头像、服务器 IP、终端历史和任何 API Key。

## 2. 录制前准备

### 2.1 数据与状态

- 文献库预置：Transformer v1/v7、BERT、GPT-1/2/3、ResNet、Vision Transformer；
- 长文档预置并完成解析，以便直接展示目录和进度记录；
- 准备一个 CSV：日期、方法、准确率、训练耗时、三次重复观测；
- 准备一个架构图输入：`PDF → 解析 → BGE 检索 → DeepSeek → 引用校验 → PDF 高亮`；
- 准备两个问题：
  - 正向：`比较 GPT-1、GPT-2、GPT-3 的参数量和上下文长度演进，并逐项给出原文证据。`
  - 负向：`比较 ResNet 和 ViT 训练产生的精确 kg CO₂e 排放量。`
- 预热 DeepSeek、BGE-M3 与 Reranker，确认状态页为可用；
- 清空无关对话，只保留用于演示的文献。

### 2.2 录屏设置

- 浏览器缩放 100%，分辨率 1920×1080；
- 鼠标指针开启轻量高亮，关闭系统通知；
- 使用最终域名，不出现 `localhost`；
- 字幕安全区距离底边至少 80 px；
- 录制一条完整主版本，再单独录制每个关键点击作为补镜头。

## 3. 分镜与解说词

### 0:00–0:25　开场与定位

**画面**

1. 2 秒项目名称片头；
2. 打开 PaperPilot 首页，缓慢移动到五个工作区入口；
3. 屏幕角落显示一句话定位：`从 PDF 原文到可追溯研究结论`。

**解说词**

> 科研问答真正困难的不是生成一段流畅文字，而是确认每个结论来自哪篇论文、哪一页和哪一段。PaperPilot 是一个原文证据驱动的科研助手，覆盖 PDF 解析、文献问答、双语阅读、论文追踪、引用图谱和研究材料生成。

### 0:25–0:55　系统架构与抗幻觉思路

**画面**

1. 切到一张简洁架构图；
2. 依次高亮 `Document AST → BGE-M3 → Reranker → DeepSeek → 引用白名单 → PDF 锚点`；
3. 右下角显示 Lite/Standard 两种模式。

**解说词**

> 系统不会直接把整篇 PDF 交给模型。文献先被解析成带页码、块编号和坐标的结构化 AST，再由 BGE-M3 和重排模型筛选证据。DeepSeek 只能引用本轮允许的证据编号，服务端还会复核引用和数值；证据不足时拒绝形成结论。轻量模式无需下载模型，标准模式用于完整语义检索和比赛验收。

### 0:55–1:40　上传、版本去重与解析

**画面**

1. 进入“文献库”；
2. 上传 `1706.03762v7.pdf`，快速剪辑到解析完成；
3. 再上传 `1706.03762v1.pdf`；
4. 特写版本提醒、`建议保留 v7` 和版本差异入口；
5. 打开结构信息，掠过作者、摘要、三级目录、表格、图表、公式和参考文献数量。

**解说词**

> 上传后，后台按页解析并持续写入检查点。第二次上传旧版 Transformer 时，系统不是根据文件名判断，而是综合 arXiv 版本、题名和正文指纹，识别为高重合版本，并建议保留较新的 v7。用户可以查看带页码和 Block ID 的修订差异，再决定替换、保留现有版本或两版并存。

### 1:40–2:25　版式阅读、引用跳转与长文档

**画面**

1. 打开 Transformer PDF 阅读器；
2. 展开三级目录并跳转到指定章节；
3. 点击正文 `[11]` 跳到 References，再点击“返回正文”；
4. 展示一条问答证据的页面高亮；
5. 快切 541 页文档的解析进度与目录，显示“可恢复”。

**解说词**

> 阅读器保留原始单双栏、公式和表格。目录按 AST 层级加载，正文引用和 References 可以双向跳转。问答证据携带 PDF 坐标，因此缩放后高亮仍对齐原文。对于 541 页长文档，系统每 25 页原子保存检查点；测试中断后从下一批继续，而不是整本重跑。

### 2:25–3:35　单篇问答、多文比较与拒答

**画面**

1. 回到“文献问答”，输入 Transformer 的优化器问题，例如 `β1、β2 设置是多少？`；
2. 点击答案中的证据，跳到原页；
3. 切到“多文对比”，选择 GPT-1/2/3，提交预设问题；
4. 特写参数量、上下文长度、逐论文证据矩阵和 Trace 中的 `reranked`；
5. 提交 CO₂e 负向问题，展示证据不足拒答。

**解说词**

> 单篇问答返回答案、原文摘录和页码。多文比较不是把所有段落混在一起，而是对每篇论文分别检索和重排，再按比较维度组织证据。这里可以看到 GPT 系列参数规模和上下文长度的演进，每个数值都能回到对应论文。对于论文没有报告的精确碳排放量，系统明确提示证据不足，不用模型估算一个看似合理的数字。

### 3:35–4:20　双语阅读与学术翻译

**画面**

1. 在 PDF 中划选一段英文并点击翻译；
2. 打开当前页双语模式；
3. 分别拖动左右两侧，展示同步滚动；
4. 关闭同步开关并单独滚动一侧；
5. 快切整篇翻译进度和 Markdown/HTML 导出按钮。

**解说词**

> 划词翻译只处理选中内容，并保护公式、代码、引用和数字。页级双语使用 Block ID 对齐原文和译文，两侧可双向同步，也可以关闭联动独立阅读。整篇翻译在后台逐页缓存，失败后可续跑，最终导出带页码和块标识的 Markdown 或自包含 HTML。

### 4:20–5:05　论文发现、推荐与引用图谱

**画面**

1. 输入论文题名或 arXiv ID，展示检索结果和安全导入；
2. 展示一个 arXiv 订阅、GitHub 代码标识和推荐理由；
3. 点击点赞或点踩；
4. 切到引用图谱，高亮基石、桥接和衍生节点；
5. 展示 Future Work 时间线与两侧证据。

**解说词**

> PaperPilot 可以按题名、DOI 或 arXiv ID 检索并导入开放 PDF，也能定时刷新 arXiv 订阅。推荐同时考虑本地文献相关度、时间和开源代码，点赞与点踩会更新兴趣画像。引用图谱只使用库内可核验的 References 建边，并用局部 PageRank 标记基石和桥接论文。Future Work 不会武断宣布已解决，而是展示旧方向和新进展证据，交给研究者确认。

### 5:05–5:50　写作框架、架构图和数据可视化

**画面**

1. 输入一个研究 idea，展示 Abstract、Introduction、Related Work 框架；
2. 特写经过核验的 References 和缺失字段警告；
3. 打开架构图工具，依次切换 Mermaid、Graphviz、TikZ 和 Matplotlib；
4. 上传 CSV，展示折线或柱状图、误差棒、三维雷达图与 Figure Caption。

**解说词**

> 写作工具先检索本地论文，再整理框架。最终 References 从持久化元数据重建，模型不能凭空写入书目。架构图可导出四种可编辑脚本。CSV 工具会检查字段和缺失值，生成图表、可复现的 Matplotlib 代码以及只描述真实数据趋势的学术图注；单次观测不会被包装成虚假的误差范围。

### 5:50–6:30　测试结果与工程可复现性

**画面**

1. 展示验收结果信息图，数字依次出现；
2. 快切 GitHub 目录、README、测试脚本和 Git 历史；
3. 展示公网 HTTPS 与评审登录页面，但隐藏域名管理和服务器后台。

**解说词**

> 固定测试集中，Transformer v7 到 v1 的版本门禁 8 项全部通过；扫描替代样本完成 15 页 OCR；真实 541 页教材通过断点续跑。七篇论文建立了 1405 个向量点，BGE 加 DeepSeek 的后端三轮共 15 个用例通过，完整浏览器两轮各 5 个用例、每轮 14 条指定事实均带原文页码。它们是固定金标结果，不代表开放域准确率。仓库保留依赖锁、测试脚本、验收记录和完整 Git 历史。

### 6:30–6:55　创新点、边界与结束

**画面**

1. 显示三条创新点：`坐标贯穿全链路 / 降级与验收分离 / 多文公平取证`；
2. 显示边界：`官方扫描件待复验 / 复杂公式与表格仍需专用模型`；
3. 项目名称、仓库地址、在线演示地址和评审账号提示收尾。

**解说词**

> PaperPilot 的核心不是让模型说得更多，而是让结论能够返回原文、让失败能够被识别、让研究材料能够继续编辑。当前复杂公式和表格仍有边界，组委会原始扫描件也将在提交前复验。以上是 PaperPilot，感谢观看。

## 5. 公网部署完成后的替换项

录制前必须把下列占位状态替换为真实信息：

- `[最终公网 URL]`；
- `[评审账号获取方式]`；
- `[最终 Git Tag / Commit SHA]`；
- `[服务器 CPU / GPU / 内存]`；
- `[最终 Standard 或 Lite 运行模式]`；
- `[官方扫描 PDF 最终复验结果]`。

如果标准 GPU 服务器费用过高，可在录制和评审期临时购买，提前完成镜像构建和模型缓存；评审结束后再按比赛规则决定是否释放。无论选择 CPU 或 GPU，视频中展示的运行模式必须与外网验收结果一致。

## 6. 现场失败备用方案

| 风险 | 录制前处理 | 备用镜头 |
| --- | --- | --- |
| DeepSeek 短暂超时 | 预热并检查余额 | 使用同一部署当天录制的完整成功补镜头，不伪造页面 |
| BGE 首次加载慢 | 提前下载模型并保持容器健康 | 先讲解析，再切回检索镜头 |
| 541 页解析时间长 | 预先入库，只展示历史进度与恢复记录 | 使用验收信息图和 Manifest 画面 |
| arXiv API 限流 | 提前准备一个已刷新的订阅 | 展示已持久化推荐并说明刷新机制 |
| PDF 上传网络慢 | 使用体积较小的 Transformer 样本 | 剪辑等待时间，保留上传开始与完成状态 |
| 公网临时不可用 | 录制前从第二网络执行门禁 | 暂停录制并修复，不能用 localhost 冒充在线演示 |
