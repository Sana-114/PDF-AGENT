# 扫描表格行列恢复验收

本轮沿用 11 月 1 日的三份官方文件、SHA-256 和 32 个原页检查。另从扫描版 Transformer 物理第 9 页表 3 的 (A) 组选择 4 行，每行核对 PPL 与 BLEU 两个数值。独立记录新增 8 项，便于和上轮直接比较。

三份文件共 571 页，全量重解析后原检查从 27/32 提高到 **29/32**，新增抽查 **8/8**。表 3 的 base 行 13 个单元格全部匹配。表 4 两个 Transformer 行分别为 WSJ only, discriminative／91.3 和 semi-supervised／92.7。已有 BLEU 两列、教材三个简单公式、矢量原页四个锚点保持通过。仍失败的是扫描训练成本指数、扫描 attention 公式和教材公式（2.5）。后端 1,761 项通过，零失败、错误或跳过；变更文件 Ruff 通过。无 LLM 调用。各项实测值见[最终验收 JSON](evidence/scanned-grid-acceptance-2026-11-02.json)。

## 修复与原页依据

原扫描表格检测把两条内部列组分隔线当作左右边框，导致表 3 的模型名与右侧指标落在裁图范围之外。现在检查多条横线共同支持的左右边界，对满足条件的密集表格逐行带读取。用一行的数值位置建立列，再要求另一行的数值与已有列位置对齐。局部 OCR 投影回 PDF 页坐标。

表 4 的部分行已经有模型名和分数，但缺少中间的训练条件。系统检查行高、上下边界和左右文本范围，用单行真实单元格裁图重新读取。包含多行的大区域不用于填补单个条件。

稀疏行对小数点敏感。另一种分辨率在同一坐标读到带小数点的数值，且去除小数点后的所有数字都相同时，才采用该读数。首轮新增检查中 32 头模型的 BLEU 被读作 254，原页为 25.4；此失败保存在本地首轮报告中。

影响范围为扫描表格。更新 OCR 解析器版本后，已有入库文档需重新解析才能应用修复。表头中的数学记号、合并的分组标签和表内其余数值仍需独立核对。

## 复现

在项目根目录配置后端依赖和 Tesseract 语言包后，使用独立的新目录运行：

```powershell
python backend/scripts/verify_official_structure.py --corpus 科研小助手/pdf --output backend/tmp/scan-grid-review
```

带有未通过条件时脚本返回非零。原始 PDF、检查点与本机临时数据留在本地。首轮及最终报告位于 `backend/tmp/structure-nov02/official/` 和 `backend/tmp/structure-nov02/final/`。
