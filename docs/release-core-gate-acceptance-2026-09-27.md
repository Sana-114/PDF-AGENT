## 验证方式与修复

- PDF 门禁运行 `pwsh -NoProfile -File scripts/run_release_pdf_acceptance.ps1`。脚本先对源文件做 SHA-256 校验，再在运行中的后端镜像内调用实际解析和重复检测代码；机器报告在 `backend/tmp/stage65-release/`，不会入库。
- 问答门禁运行 `pwsh -NoProfile -File scripts/run_real_pdf_comparison_e2e.ps1 -Gpu -Build -Rounds 3`。七篇 PDF 上传/索引一次，三轮独立调用模型；每轮都必须要求 DeepSeek、`reranked` 证据、有效 PDF 页码/块/BBox、跨文献声明及全部金标事实。无 NVIDIA 运行时去掉 `-Gpu`；需要本地 `.env`、`.env.bge` 和有效 DeepSeek Key，运行会产生 API 费用。
- 早期重复运行曾捕获 ResNet 的 Related Work 混入正文方法、BERT/GPT-1 仅分别罗列事实、DeepSeek 断连降级和金标中文同义词/有效页码误判。这些失败未算通过。服务现在偏好论文本身方法证据，对短暂断连做有上限重试；仅在两条已分别核验的同维度事实都存在时，生成不添加新推断的双来源并列声明。审计将此类程序派生声明与模型生成声明分开计数。金标仍要求同一声明的指定来源和页码，不允许只靠回答关键词通过。
- 后端门禁的 GPT-1/2/3 问题每篇使用 5 条证据，但页面原先固定为 4 条，导致两次独立浏览器调用都漏掉 GPT-3 Pre-LN 原文事实。现将 API 默认值、页面请求与门禁统一到 5 条，并在浏览器脚本中断言请求预算不低于金标预算；修复后的该问题专项浏览器验收通过，六条指定事实和 PDF 跳转均完整。
- 页面复测还捕获到两种**生成阶段**问题：模型有时看到了 GPT-2/3 参数量原文，却未在最终声明中写出；有时把“没有精确 kg CO₂e 测量值”包装成跨文献差异。前者仍需通用的目标事实完整性复核，不能用增加检索量冒充解决；后者已增加原文单位与数值双来源门禁，缺少任一篇的精确测量锚点就返回证据不足。修复后负例专项浏览器用例通过，返回零条声明与明确的证据不足状态。
- 最终后端全量单元测试及 Ruff 检查通过；前端 15 项测试和 TypeScript 类型检查通过。运行时 JSON 与截图不上传公开 Git 仓库。

## 未覆盖范围

本轮三轮通过是对固定七篇论文、五组问题的后端抽样证据，不是任意提问的正确率保证；自动金标也不能替代非数值语义的人工逐句审查。**完整浏览器五组独立调用尚未稳定通过**：虽然上传、PDF 跳转和 GPT 专项复测通过，完整页面运行仍出现模型漏写已检索到的参数量事实。浏览器失败报告保存在 `backend/tmp/stage65-release/browser-final-v3.json`，并未计入后端 3/3 成绩。仍需拿到组委会原始扫描 PDF 后复测，并对扫描机构、复杂表格和 541 页教材表格开展专项验收。公网在线演示、评审账号、视频和不超过 30 页的技术 PDF 属于独立交付项，不由本门禁证明。
