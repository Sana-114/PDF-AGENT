# 中文正文英译验收

模块六要求把中文摘要或全文译为学术英文。实际入口是写作区的「学术翻译」：选择中文、English 和「论文正文」，粘贴文本后可编辑、保存、重新载入及导出双语 Markdown。单次输入上限为 24,000 个字符。

本轮使用[中文研究札记](../backend/tests/fixtures/academic_paper_zh.md)，根据[官方测试集的既有结果](official-screening-2026-11-06.md)撰写，含摘要、方法、结果、讨论及复现说明。它是补充样本，未使用私人文稿。全文 1,988 字符、44 段，其中一个代码块内含空行。两轮均使用真实 DeepSeek Flash，每轮两批，以同一输入比较。两轮只算一篇样本。正式文献库、预提交压缩包与视频均未更新。

## 通过项

| 检查 | 实测 |
| --- | --- |
| 段落与术语 | 最终译稿 44 段，三个指定术语分别在其原段保留 5、3、5 次 |
| 公式、代码及引用 | 两个公式、两处代码、两个引用标记和十处数字受保护。Python 代码块含空行，下载件逐字保留 |
| 草稿与下载 | 真实 API 保存并读回。Edge 从历史稿载入，将下一篇的语言选择改为英文→中文，再实际下载。文件仍标注中文→英文，双语正文与保存稿逐字相同 |
| 近上限输入 | 离线用恰好 24,000 字符的单段输入，将切点放在公式占位符内，验证改为三次有界调用，返回仍为一个段落。本项使用测试提供方 |
| 负例 | 两个段落互换受保护数值会被拒绝；与汉字紧邻的小数、百分比和单字术语不再截断数字或破坏代码占位符 |

此前中文示例「共39份，比例为91.5%」只保护到了尾部的「5%」。旧学术翻译也只校验全文占位符总量，如果两段数值互换，总量仍正确。本轮修复了数字边界、分段归属及单段请求超长。前端保存和导出改用生成时的语言与文本类型。浏览器首次因检查脚本使用过严的表单定位超时；修正定位后实际下载通过，没有重新调用模型。

## 科学内容复核

对照中英稿，741 对、737 对、4 对中识别 3 对，以及 0.5148 低于 0.55 均保留。对 [17] 与 [16] 的用途区分、无法把一次漏报分别归因于扫描和版本修订、结论只覆盖固定测试集，也保留在对应段落。

两版译文均有需要编辑的地方。首轮将一次漏报译为复数；最终稿后文已使用单数，前一句仍写作 “The misses occurred”。固定术语在正文里的冠词有所改善，但英文标题中保留小写 “citation function” 较生硬。按当前结果，保存、导出和结构保真可用于演示，最终英文稿仍需审校。[真实浏览器下载件](evidence/academic-zh-en-sample-2026-11-06.md) · [分项结果](evidence/academic-zh-en-2026-11-06.json)

## 复现

从仓库根目录，在后端环境设置 `PYTHONPATH=backend` 并配置 DeepSeek 后运行以下命令。脚本使用新建的隔离库，保存两种语言的原文和最终返回；输出目录必须尚未存在。Node 需支持直接加载前端 TypeScript 导出函数。真实浏览器下载是上述脚本之外单独完成的检查。

```powershell
python backend/scripts/verify_long_academic_translation.py --output backend/tmp/academic-zh-review --allow-cloud
```
