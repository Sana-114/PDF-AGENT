## 修复效果

- 扫描行的空白指标列与被 OCR 拆开的成本单元格可能同时出现，使识别片段数恰好等于表格列数。现在根据已建立的列位置纠正明显偏移的数字。Deep-Att + PosUnk Ensemble 的 EN-DE 恢复为空，EN-FR 恢复为 `40.4`。
- 公式候选利用同一行、相邻字体大小和基线的差异恢复数字上下标，原始文字保留。教材（2.4）两个参数的下标 `0`、`1` 得以区分。多块分式和求和仍按失败保留。
- 矢量检测器的平铺坐标列表会省去合并单元格中的空位。改为按实际行和列取坐标，表 4 的 `91.3` 从原先指向训练条件的位置恢复为该数值的位置。
- 更新原生和 OCR 解析器版本。重新解析后才能得到新结果，已有文献库未执行迁移。

## 复现

从项目根目录配置后端依赖与 OCR 语言包，设置 `TESSDATA_PREFIX` 后运行：

```powershell
python backend/scripts/verify_official_structure.py --corpus 科研小助手/pdf --output backend/tmp/structure-audit-new
```

脚本要求新的输出目录，保留检查点与失败结果。存在未通过条件时返回非零状态。修复前后的本机诊断和最终报告分别保存在 `backend/tmp/structure-nov01/` 及其 `final/` 子目录。初次导出教材摘要时，诊断脚本误取了原生解析器没有的 OCR 元数据；保留原检查点后完成导出，最终验收重新从三份原件解析。

后端离线回归 **1,759 项通过**，0 失败、错误或跳过。此次专项不计入跨论文问答、推荐、多用户或交付验收。
