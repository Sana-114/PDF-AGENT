# PaperPilot 科研助手 · 作品介绍

## 01 项目概况

PaperPilot 面向需要反复阅读、比较和整理论文的研究者。用户将 PDF 放入文献库后，可以在原版页面中阅读，围绕选定论文提问，查看答案引用的原文，并继续完成翻译、引用关系分析和研究材料整理。

项目以“每条重要结论能够回到原文核对”为设计重点。模型负责组织语言和比较材料，检索、页码定位、数值统计及引用书目由相应程序处理。缺少依据时，系统应说明缺失，而不是补写一个看似合理的答案。

### 一条常用操作路径

上传论文 → 检查解析与版本 → 选择研究范围 → 提问或阅读 → 点击证据核对 → 导出翻译、研究提纲或图表。

## 02 六类功能如何使用

| 功能 | 用户操作与结果 |
| --- | --- |
| PDF 管理与解析 | 单篇或批量上传；检查 OCR、结构节点与解析状态；出现版本候选时，选择保留、替换或并存，并查看差异。 |
| 论文问答与比较 | 选择一篇或多篇文献，询问方法、训练设置或指标；回答附证据，点击后进入对应原页。 |
| 阅读与翻译 | 用目录导航和引用链接阅读；划词、按页或全文翻译；中英联动阅读，并导出 Markdown／HTML。 |
| 查找与追踪 | 按题名或标识查找论文、沿参考文献继续查找；设置 arXiv 订阅，结合本地兴趣及代码线索筛选。 |
| 图谱与研究脉络 | 选择文献集合，观察局部引用关系；生成有出处的综述，核对未来计划与后续论文证据。 |
| 写作与图表 | 根据 idea 和选定文献生成写作框架；导出拓扑脚本；上传 CSV 生成图表及基于数据的图注。 |

### 使用时如何判断结果

问答先核对来源和单位；跨论文比较需要明确比较对象和指标口径。全文翻译可以恢复未完成页，但仍需审校术语与学术表达。局部图谱的中心节点只说明所选集合中的位置，不代表整个领域的影响力。

### 需要明确的边界

公式抽取提供候选 LaTeX，复杂公式与表格仍可能需要人工修正。翻译导出采用 Markdown／HTML，未提供原位翻译 PDF。引用作用筛选属于辅助判断，不能可靠地自动裁定所有“应付式引用”。多用户推荐与隔离仍是扩展方向。

## 03 安装与首次使用

### 推荐运行方式

准备 Docker Desktop／Docker Compose、PowerShell，以及访问模型下载源和 DeepSeek API 的网络。解压源码后，在项目根目录操作。标准模式会下载 BGE 模型和容器镜像，源码包本身不包含这些大文件。

1. 复制 .env.example 为 .env，复制 .env.bge.example 为 .env.bge。
2. 在本机 .env 设置 LLM_PROVIDER=deepseek、LLM_MODEL=deepseek-flash、LLM_BASE_URL=https://api.deepseek.com，并填写自己的 LLM_API_KEY。
3. 执行 pwsh -File scripts/start.ps1 -Mode standard；有兼容 NVIDIA GPU 和容器运行环境时，可添加 -Gpu。
4. 按启动日志访问前端。模板默认端口为 3000；若修改 FRONTEND_HOST_PORT，以实际配置为准。
5. 上传一份可公开使用的 PDF，等解析与索引完成后，选择它提问，并点击回答中的证据检查原页。

### 轻量模式与真实模型的区别

scripts/start.ps1 的默认模式是 lite；环境模板默认 LLM_PROVIDER=mock。它们便于先检查界面和基础流程，不代表已开启 BGE 与真实 DeepSeek。展示完整链路应采用标准模式并完成模型及 API 配置。

### 数据与配置

数据库、上传文件和索引保存在运行数据卷中。密钥只放在本地环境变量或服务器环境中，不进入前端和源码包。官方测试 PDF 及模型权重未随包分发；评审可导入自行持有的测试文档。详细启动、端口、CPU／GPU 和部署配置见源码 README、scripts 与 deploy 目录。

## 04 AI 技术与关键实现

### 从 PDF 到可追溯的回答

PDF → PyMuPDF／OCR → 带页码、块编号和坐标的 Document AST → 分块与索引 → 混合召回 → 重排 → DeepSeek 回答 → 声明及引用检查 → 原文定位。

| 技术 | 在项目中的职责 |
| --- | --- |
| BGE-M3 + Qdrant | 将文本转为检索向量，结合稀疏／词项检索寻找相关证据。 |
| BGE Reranker | 对候选片段重新评分，将更相关的内容放到模型输入前部。 |
| DeepSeek Flash | 基于给定证据生成回答、翻译、综述及写作内容；部分声明另行校审。 |
| Harness 与工具注册 | 管理检索、目录、结构和表格读取工具，记录执行过程、返回状态及证据。 |
| FastAPI、Celery、PostgreSQL | API、异步解析／翻译／订阅任务及业务状态存储。 |
| Next.js、React、PDF.js | 文献工作区、原生 PDF 阅读、证据跳转及双语交互。 |

### 减少错误的具体做法

长文档分批解析并保存检查点；回答按照选定文献范围检索；引用使用已有证据编号；数值比较保留单位、条件与论文身份。对因果和数学关系增加语义校审，防止“引用存在但结论方向写反”。这些检查可以降低风险，不能保证模型从不出错。

### 开源依赖与项目来源

项目不是基于某个现成应用改造。使用上述开源框架、预训练模型和第三方 API 完成功能集成，依赖及版本以 requirements、package-lock 和 Compose 文件为准；不将这些依赖宣称为自研成果。

## 05 亮点：答案能够回到原文

![图 2：真实问答与原页定位。硬件问题引用 Transformer 原文，阅读器显示对应页及证据区域。](docs/assets/pre-submission/qa.png)

系统保留“问题、回答声明、证据编号、页码和坐标”的关联。用户无需只相信一段流畅回答，可以逐项核对原文。跨文献比较也采用相同方式，避免把不同论文的参数、任务或指标拼接成一个结论。

![图 3：实际双语阅读界面。原文与翻译对应显示，阅读过程中可以联动定位。](docs/assets/pre-submission/bilingual.png)

翻译保留公式、代码、数字及引用的保护规则；逐页保存结果并支持恢复。已验收的 Transformer 全文样本包含 15 页，提供译文及双语两种内容的 Markdown／HTML 导出。此处证明流程可完成，不等同逐句翻译质量均已通过人工审稿。

## 06 亮点：研究关系与数据产出

![图 4：20 篇文献的局域引用图谱。节点角色根据当前集合中的引用关系计算。](docs/assets/pre-submission/graph.png)

图谱将引用关系与原文阅读连接起来。Future Work 核对把早期论文的明确目标与后续证据配对：有充分支持时，在限定目标内排除；只部分解决或不相关时保留，并允许人工覆盖。它不声称自动穷尽全球最新研究。

![图 5：CSV 图表工具的实际界面。此图使用合成演示数据，不能作为论文实验结果引用。](docs/assets/pre-submission/charts.png)

图表数值来自 CSV 和确定性统计，可生成折线、柱状及雷达等图表，并整理描述核心趋势的图注。写作框架使用实际文献元数据构建参考书目；拓扑脚本支持 Mermaid、Graphviz、TikZ 和 Matplotlib，便于继续编辑。

### 统计口径与保留项

官方测试集历史覆盖涉及 39 份 PDF，但本轮没有把 39 份的全部功能逐一重新跑完，不能将本表转换成“39 篇全部通过”或统一准确率。表中分母是各自测试项数；它们不相加，也不代表开放问题的准确率。
