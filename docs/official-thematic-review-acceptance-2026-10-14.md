# 主题综述与写作续验（2026-10-14）

本轮实现主题化综述链路，并修复五条保存输出暴露的发布漏洞。**本地工程检查通过，科学内容质量和最后运行版尚未放行。** [机器记录](evidence/official-thematic-review-acceptance-2026-10-14.json) 保存四次真实请求、两次零调用回放、候选指纹与 43 项产物／源码哈希。

## 完成的改动

1. 综述由最多四个主题组织，每条陈述显式标明单篇／跨篇及有依据／暂无依据。跨篇必须引用不同原始论文的正文；同篇多个摘录、同篇提到多个方法及仅书目关联均不算跨论文推理。
2. 主题注册表、引用 ID、类型和长度都有检查。未知主题、无效引用、类型与来源数量不一致的整条暂缓，不截断改写；没有依据时不生成不存在的科学结论。
3. API 返回主题及已发布陈述的索引，前端按主题展示。分组只能使用最终发布条目，不会把被暂缓的事实重新显示出来；旧接口响应仍可展示。
4. 补拦“故需学习率预热”的无条件必要性概括、缺少对应 FLOP 原页的计算量增加声明，以及将来源不足说明混入事实的条目。这些是窄范围防护，不是通用科学真值判断。
5. 写作补拦表格实验对象与生成主体不一致，以及将特定已引用工作扩大为所有先前工作的陈述。不硬编码测试论文名称或数值，也不自动改写错误陈述。
6. 最后提示加入同篇共享的 `paper=P1/P2…` 短编号，帮助区分“多个方法”和“多篇论文”。它仅用于主题综述，不改普通问答输入；尚未获得该最后候选的新生成确认。

`source_checks_passed` 仅表示生成来源链接等机器检查通过，不是语义正确或整份写作可发表。四次生成指纹与最后源码不同；最后源码未重新生成，不能拼成“最后同版通过”。
