## 重测暴露并修复的问题

### 1. 排序错误改用同义词后绕过防护

模型的原始参数回答将 BERT 对应模型写成“第二大”，而原文是“第二小”。此前检查能识别“等价/对应”，却漏掉“等同”。现在补齐有限的中文、英文等价词表达，错误关系声明整条移除，不悄悄纠正或改写它；正确关系和不相关比较保留。

### 2. 有据参数答案被句式和别名误拒绝

模型已经给出参数表精确数值，并用后续论文的等价说明推断原始 GPT，但完整性规则不认识“参数量分别为……”以及“数值对应原始 GPT 的参数量”这种反向表达。

现在支持明确的参数列表、严格的 `原始 GPT / original GPT` 别名与显式反向赋值。别名后带代际数字时不会被改成 GPT-1；也不把训练 token 数或其他规模列表算成模型参数。没有在生产代码里写入原题参数答案。

### 3. 正常句式修复再次引入撤回漏判

负例发现“数值不是可确认结论”、先赋值再说“只是猜测”，以及重复模型名后声明“未知”等表达仍可能残留肯定赋值。补齐相应否定和撤回检查：同一模型的明确撤回要生效，另一模型的不确定性不能抹去已有的正确对应。反向赋值同样受撤回约束。

### 4. 完整性标志能拒绝，却仍发布不可靠窗口推断

原上下文回答仅引用训练连续序列长度，就说可以据此推断上下文长度。虽然答案被标成不完整，这个推断仍被发布。新增有限的语义检查：可检测的“训练长度可作为窗口”声明，若仅有训练序列来源、没有实际窗口定义，会被移除。

真正的训练事实、明确拒绝此推断的表述，以及原文明确报告完整 context window 的情况不会被该检查误删。它不是通用语义证明器；其他自由表述、跨声明矛盾和所有表格单元格对应仍需原文审查。

### 5. 模型过度要求字面标签，仍需要真实生成确认

本轮上下文答案以原文没有单列“最大上下文窗口”字样为由拒答；但原文包含架构配置的 context size 和 full context window。生成契约已说明：可以报告受原文支持的配置及来源局限，无须原文出现字面 `maximum`，但不能把只有训练序列长度的句子当窗口，也不能声称未报告的普适上限。

同时要求每个请求模型单独给出字段对应，来源限制单独解释，避免模型名与数值隔在复杂段落里。**这部分提示词效果尚未由新增真实调用验证**；不能将其当成上下文题已通过。

### 6. 重放工具也补了边界测试

支持选择这两道原题，仍要求选择非空、唯一且为已知原题；预期缺项完全吻合，并验证指定语义冲突确实被拦截。记录实际运行源码哈希。默认三题重放仍可用，不实例化云端模型，不改原始输出或原题数据。

GPT-3 参数表的一条多余声明还包含“8 个模型”，但只引用的表格块并没有明文的数字 8；它已被严格数值门禁拒绝。同页另一个已引用段落确实明文报告 8 种规模，所以支持主要 GPT-3 结论的另一条声明保留。没有为通过测试而放宽所有未引证数值，也没有自动替模型补引用。
