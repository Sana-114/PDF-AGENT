# 跨页表格续接验收（2026-09-17）

## 目标

补齐不依赖 LLM 的核心解析能力：当一个原生 PDF 有框表格从上一页底部延续到下一页顶部时，将两个页面片段恢复成一个结构化表格，同时保证第二页单元格仍能作为独立证据跳回第二页，而不是错误锚定到第一页。

## 判定策略

续接器只在以下条件同时满足时合并：

1. 两个表格位于严格相邻页面；
2. 前一片段下边界进入页面底部 28% 区域，后一片段上边界进入页面顶部 28% 区域；
3. 列数相同且至少为两列；
4. 左右边界按各自页面宽度归一化后偏差均不超过 8%；
5. 图注表号相同，并有 `continued/续表/接上页` 信号或重复表头；若续页没有图注，则必须有完全一致的非空重复表头。

普通页面仍使用 `Table N / 表 N` 图注门控。唯一的额外扫描是：上一页已检测到贴近页底的表格、下一页当前没有表格且存在原生文本层时，对下一页执行一次原生网格检测；只有列结构、边界和重复表头均匹配才接纳，因此不会恢复任意无图注页面中的孤立布局。

## 结构化结果

合并后的 `TableNode` 保留首段 `table_id`、图注和完整 Markdown，并新增：

- `segments[]`：每段的 `page_number`、`bbox`、`row_start`、`row_end` 与可选 `caption_block_id`；
- `cells[].page_number`：每个单元格实际来源页；
- 重复表头只保留一次，后续段行号重新映射到合并表格。

Chunking 不把整个跨页表格只锚定到首页。每个 `segment` 单独生成表格证据，保留统一表头与该页数据、该页 BBox、分段节点 ID 和续页图注块 ID（如果存在）。

## 可复现测试

测试使用 PyMuPDF 生成两页 A4 矢量 PDF：第一页的 `Table 7` 位于页底，包含表头及两行数据；第二页顶部没有续表图注，只有相同表头和另外两行数据。Poppler 以 120 DPI 渲染后确认：

- 两页均为标准 A4，表格线完整；
- 第一页表格确实接近页底，第二页表格从页顶开始；
- 所有单元格文字清晰，无裁切、重叠或黑块；
- 第二页没有可供原有图注门控使用的 `Table N` 文本。

运行专用测试：

```powershell
docker compose exec -T backend python -m pytest `
  tests/test_table_stitching.py tests/test_retrieval.py -q
```

结果为 9 项通过，覆盖：真实两页 PDF 合并、重复表头去重、两段行范围、单元格真实页码、第二页分段证据、不同编号表格防误并，以及现有结构化检索回归。

全量后端回归为 126 项通过，Ruff 全部通过。随后重新解析真实 `1706.03762v1.pdf`：仍得到 Table 1-4 共 4 个独立表格，行数依次为 6、13、7、6，每个表格均只有一个分段且没有告警，说明续接规则没有把该论文相邻页面的独立内容误合并。

## 当前边界

- 本轮面向原生文本层的规则表格；OCR 跨页表格仍依赖每页图注引导的栅格恢复。
- 不推测没有重复表头、没有同编号续表标记的弱信号续页。
- 复杂纵横合并单元格、旋转表格、跨页单元格以及页面间列结构变化仍需专用表格模型。
- 当前官方比赛 PDF 尚未提供跨页表格金标，因此该用例属于可复现工程回归，不替代组委会样本验收。
