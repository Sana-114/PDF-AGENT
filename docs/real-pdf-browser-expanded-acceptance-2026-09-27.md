# 真实 PDF 浏览器闭环与跨领域扩展验收（第 64 阶段，2026-09-27）

## 范围

接续第 63 阶段的 BGE-M3 + BGE Reranker + DeepSeek Flash 后端门禁，本轮把固定 SHA-256 的语料从五篇扩大到七篇：Transformer v1、BERT v2、GPT-1/2/3、ResNet、Vision Transformer。来源与哈希见 `docs/pdf-regression-corpus.json`。五组问题包括 BERT/Transformer、GPT-1/2/3、BERT/GPT-1、ResNet/ViT，以及无精确排放量证据的拒答；正向问题共 14 条指定来源和页码的事实金标。

ResNet 原论文第 2–3 页描述恒等捷径与 `F(x) + x`，ViT 原论文第 3 页描述图像块序列、Transformer Encoder、多头自注意力及 LayerNorm 位置。两篇的相关页均已渲染并人工查看。ViT 的 image patches 与 ResNet 的 identity shortcut 是跨领域比较的主证据；ResNet 第 2 页的 VLAD/dictionary 属于 Related Work，不得误称为 ResNet 自身方法。

## 实测结果

- 七篇论文上传/解析就绪后，BGE-M3 1024 维索引的 **1,405 个文本块与 Qdrant Point 逐篇一致**；BGE 服务健康探测通过。
- 最终镜像的后端严格评测 **5/5 用例、14/14 原文事实通过**。每条入选证据均为 `reranked`，有有效 PDF 页码、块和坐标；两个新用例分别覆盖 NLP 预训练差异与视觉模型架构差异。
- Edge 无头浏览器通过真实页面完成一次重复 PDF 上传、五组问题选择与提交、显示回答与 API 一致性检查、14/14 页面金标事实检查、四次引用按钮到 PDF 指定页的高亮跳转，以及排放量问题的证据不足拒答。该拒答允许有引文的背景事实，但不允许编造精确 kg CO2e 数值或形成跨文献结论。**5/5 浏览器用例通过，未捕获页面脚本异常**。
- 在同一最终后端镜像上，曾出现空声明的 ResNet/ViT 浏览器用例又独立重复三次：**3/3 通过**，每次均核对三条带原页锚点的事实和一次 PDF 高亮跳转；这只是小样本稳定性检查，并非准确率估计。
- 后端全量测试、前端 15 项单元测试、TypeScript 类型检查与生产前端构建通过。机器报告分别在忽略目录 `backend/tmp/stage63-real-pdf/` 和 `backend/tmp/stage64-browser/`；浏览器截图在后者的 `screenshots/`，不提交到公开仓库。

一次重复的 `-Build` 验收在前端镜像构建时遇到 Docker RPC `EOF`；该次后端金标已通过。Docker 恢复后，使用此前成功构建的、与当前前端源码一致的镜像和本轮新后端镜像，单独执行浏览器套件通过。此基础设施故障没有计为产品功能通过。

## 验证中发现并处理的问题

1. 真实 ResNet/ViT 回答曾把 Related Work 的 VLAD/dictionary 背景带入方法对比。评测新增禁用词负向门禁，生成提示明确不把先前工作归于本文方法，也不输出用户未要求的背景材料。
2. 某次较长问题的结构化回答带有声明，但 Evidence ID 全部无效，服务安全降级为抽取式回答。现在只对这种明确的引用编号错误重试一次，并再次强制原文 ID 白名单；仍失败则继续降级，严格门禁绝不会把降级算通过。大小写、方括号和空格的无歧义 ID 变体被规范为白名单中的原编号，不接受不存在的编号。
3. 浏览器选择论文和引用时，测试原先可能把 `E1` 与 `E10` 混淆。对比组件为文献和证据加入稳定的 `data-*` 定位属性及可访问的文献复选框标签；浏览器验收现在按精确 Document/Evidence ID 操作，而不是按截断标题或模糊文本匹配。
4. 排放量负例曾因模型给出带引文的 Transformer FLOPs 数据而被过严的“零声明”规则拒绝。验收改为检查证据不足标志、无跨文献结论及无捏造的 kg CO2e 数值，保留可核对的背景信息。
5. 同一组 ResNet/ViT 问题在后端门禁通过后，首次页面请求偶发返回空声明；单独复测又能满足三条金标。生成链路现对首次空声明最多复核一次，仍无直接证据时继续拒答，不能将空结果伪装为通过。

## 复现

先按 README 配好不入库的 `.env`/`.env.bge`、DeepSeek Key 与固定 PDF 语料。Windows 机器需有 Microsoft Edge；Linux 可安装 Chrome，或用 `PDFAGENT_BROWSER_CHANNEL` 指定 Playwright 支持的浏览器通道。仓库根目录运行：

```powershell
.\scripts\run_real_pdf_browser_e2e.ps1 -Gpu -Build
```

无 NVIDIA 容器运行时去掉 `-Gpu`。脚本在首次使用时安装前端测试依赖，重建后端/前端镜像，逐篇验证固定哈希、重建向量索引，先执行后端金标，再启动页面执行浏览器金标；`-Build` 可在已构建镜像下省略。脚本会调用 DeepSeek，多次运行产生 API 费用。`backend/tmp` 下的完整生成答案只用于本机审计，不随提交发布。

## 边界与下一步

本轮的一次完整严格后端与浏览器运行通过，不能等同于模型在任意问题上的稳定正确率。迭代期间严格门禁确实捕获过漏报 MLM 事实、没有合法引用的模型输出和未形成跨文献声明的回答；说明门禁有价值，也说明生成稳定性仍需继续量化。浏览器上传验证的是**已入库 PDF 的完全重复处理**，新 PDF 的首次解析由脚本后端路径验证；官方原始扫描版与 541 页教材的 DeepSeek 回答仍未在本轮覆盖。后续宜增加重复运行统计、困难负例和人工复核集，再进行公网演示验收。
