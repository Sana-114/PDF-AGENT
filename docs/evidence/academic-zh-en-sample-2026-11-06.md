# 学术论文检索系统中的重复检测与引用用途判定

## 摘要

科研人员在整理论文时，常遇到题名相同而版本不同的文件。检索结果还需要说明被引论文在正文中起了什么作用。本文考察这两类任务在一个固定文献集合上的表现。

实验材料为39份公开测试文件。我们将重复检测的输出与逐对标注比较，再从正文核对引用用途。两个任务使用不同的观察单位，因此分别报告结果。

结果表明，题名和正文信息可用于发现同一作品的不同副本。方法采用和延伸阅读在一些句子里具有明确的语言线索，但在复合句里，各篇文献承担的作用容易混淆。

## 引言

文献库中，同一篇论文可能同时以原生文件和扫描文件保存。扫描噪声会改变正文的局部词序，使文本匹配更加困难。

文件名也可能由下载网站生成。仅凭文件名合并条目，会把问题简化为命名习惯的比较，因此实验统一隐藏了原始文件名。

引用筛选则涉及另一个问题。读者需要知道作者是否真的使用了某种方法，以及哪一条书目只承担背景说明的作用。

## 材料与标注

在去重实验中，我们将测试集中的每个文件与其余文件分别配对。同一对文件只出现一次，不区分左右顺序。

若文件数为 $n$，则无序文件对的数量为 $n(n-1)/2$。这个表达式计算的是比较次数，不能用于估计论文影响力。

第一组同作品文件由两个原生版本和一个扫描版本组成。第二组包含另一篇论文的两个不同副本。

各篇论文的题名和作者为同作品标注提供依据。预期标签在运行判定程序之前确定，不能用系统本身的相似度分数来生成。

## 重复检测方法

系统使用题名与正文指纹判断两个文件是否重合。正文指纹由词串构成，文内能提取到的论文标识也可提供信息。

正文指纹反映局部词串的重叠。两篇论文讨论相似的主题，不足以说明它们是同一篇作品。

下面的示例代码说明如何枚举文件对。代码用于描述方法，不构成一次新的实验。

```python
from itertools import combinations

pairs = list(combinations(files, 2))
```

判定结果只产生重复预警。是否保留当前文件仍由使用者决定，预警本身不改变文献库。

## 去重结果

在741个无序文件对中，737对属于不同作品。程序未对这些不同作品发出重复预警。

其余4对文件属于同一作品，程序识别出其中3对。漏报发生在扫描旧版与原生新版之间。

在这次漏报中，内容相似度为0.5148，低于相应的判定门槛0.55。这个案例说明扫描噪声与版本修订可能同时降低正文匹配分数。

单个案例无法把漏报分别归因于扫描和修订。若要区分二者的影响，需要更多具有已知版本关系的对照文件。

## 引用用途判定

引用用途应在引用出现的具体位置判断。同一条书目在引言中可能用于交代背景，在方法部分也可能被直接采用。

例如，在论文讨论优化器的段落中，作者明确使用了 Adam。方法采用这一判断可以通过正文位置和书目条目复查。

另一类句子在括号中提示读者另见其他文献。延伸阅读可以作为判断该次提及的线索，但不足以据此否定整篇被引论文的价值。

对于同一句中出现多个书目键的情形，需要分别记录对应的引用位置。一条文献得到的标签不能自动转移到邻近文献上。

## 原文核对

第一组抽查选取三篇论文的8处引用。经修正后，这些位置的用途及其原文锚点均与预期相符。

随后在另两篇论文中抽查4处，其中3处符合预期。这里的抽查单位是引用出现的位置，而不是论文篇数。

在一处涉及稀疏计算的句子中，引用 [17] 对应作者采用的模式，而 [16] 用来支持对该模式表达能力的描述。

程序把两处都归为方法采用。这一结果提示我们检查同一句内部的从句边界，以及每个引用标记与其谓语之间的关系。

## 局限与结论

测试集的不同作品数量远多于同作品数量。即使总体判定正确的文件对很多，也不能据此断言同作品检测已经可靠。

本文只报告固定数据集上的观察结果。上述结果没有给出对其他学科、其他语种或更复杂扫描条件的性能估计。

正文指纹和原文锚点分别服务于作品识别和证据核查，两者应分别验收。使用者可以依据锚点复查原文，并记录有争议的判断。

后续研究可增加具有明确修订记录和不同扫描质量的样本。对于引用用途，应补充多从句、多引用的对照句，以测量错误归属的频率。

## 数据与复现说明

复查正文指纹时，评估者需要固定输入文件、文本提取结果和程序版本。若更换其中一项，应另行记录对应的文件对判定。

复查原文锚点时，可以从显示的页码找到句子，再按书目键定位条目。单凭标签名称，无法判断系统是否找到了正确的证据。

复现代码中的 `qualifies` 保存一次判定的结果。对于漏报，应同时保留预期标签、实际判定和内容相似度，以便后续独立核查。

# Duplicate Detection and citation function Determination in Academic Paper Retrieval Systems

## Abstract

When researchers organize papers, they frequently encounter files with identical titles but different versions. Retrieval results must also indicate what role a cited paper plays in the body text. This paper examines the performance of these two types of tasks on a fixed document collection.

The experimental materials were 39 public test files. We compared the output of duplicate detection with pairwise annotations, and then verified citation function against the body text. The two tasks use different units of observation, so the results are reported separately.

The results show that title and body text information can be used to discover different copies of the same work. Method adoption and further reading exhibit clear linguistic cues in some sentences, but in complex sentences the roles borne by individual papers are easily confused.

## Introduction

In a document library, the same paper may be stored simultaneously as a native file and as a scanned file. Scanning noise alters the local word order of the body text, making text matching more difficult.

File names may also be generated by download websites. Merging entries on the basis of file names alone would reduce the problem to a comparison of naming conventions, so the experiments uniformly hid the original file names.

Citation screening involves another problem. Readers need to know whether the authors actually used a certain method, and which bibliography entry serves only as background explanation.

## Materials and Annotation

In the deduplication experiment, we paired each file in the test set with every other file. Each pair of files appears only once, without distinguishing left from right order.

If the number of files is $n$, then the number of unordered file pairs is $n(n-1)/2$. This expression computes the number of comparisons and cannot be used to estimate paper influence.

The first group of same-work files consists of two native versions and one scanned version. The second group contains two different copies of another paper.

The titles and authors of the individual papers provide the basis for same-work annotation. The expected labels were determined before running the determination program and cannot be generated from the system's own similarity scores.

## Duplicate Detection Method

The system uses the title and the text fingerprint to judge whether two files coincide. The text fingerprint is composed of word strings, and paper identifiers extractable from the text can also provide information.

The text fingerprint reflects the overlap of local word strings. That two papers discuss similar topics is not sufficient to show that they are the same work.

The example code below illustrates how to enumerate file pairs. The code is used to describe the method and does not constitute a new experiment.

```python
from itertools import combinations

pairs = list(combinations(files, 2))
```

The determination result produces only a duplicate warning. Whether to retain the current file remains a decision for the user, and the warning itself does not alter the document library.

## Deduplication Results

Among 741 unordered file pairs, 737 pairs belong to different works. The program issued no duplicate warnings for these different works.

The remaining 4 pairs of files belong to the same work, and the program identified 3 of them. The misses occurred between an old scanned version and a new native version.

In this miss, the content similarity was 0.5148, below the corresponding decision threshold of 0.55. This case shows that scanning noise and version revision may simultaneously lower body-text matching scores.

A single case cannot attribute the miss separately to scanning and to revision. Distinguishing the effects of the two would require more control files with known version relationships.

## citation function Determination

The citation function should be judged at the specific position where the citation occurs. The same bibliography entry may serve to provide background in the introduction and may also be directly adopted in the methods section.

For example, in the paragraph where the paper discusses the optimizer, the authors explicitly use Adam. This judgment of method adoption can be rechecked through the body-text position and the bibliography entry.

Another type of sentence prompts the reader in parentheses to see other literature. Further reading can serve as a cue for judging this mention, but it is not sufficient to deny the value of the entire cited paper on that basis.

When multiple bibliography keys appear in the same sentence, the corresponding citation positions must be recorded separately. The label obtained by one reference cannot be automatically transferred to an adjacent reference.

## Source Text Verification

For the first group, spot checks selected 8 citations from three papers. After correction, the roles of these positions and their source anchor all matched expectations.

Subsequently, 4 positions were spot-checked in another two papers, of which 3 matched expectations. Here the unit of spot checking is the position at which a citation occurs, not the number of papers.

In one sentence involving sparse computation, the citation [17] corresponds to the mode adopted by the authors, while [16] is used to support the description of the expressive capacity of that mode.

The program classified both positions as method adoption. This result prompts us to check the clause boundaries within the same sentence and the relationship between each citation marker and its predicate.

## Limitations and Conclusion

The number of different works in the test set far exceeds the number of same-work instances. Even if many file pairs are correctly judged overall, this does not warrant asserting that same-work detection is already reliable.

This paper reports only observations on a fixed dataset. The above results do not provide performance estimates for other disciplines, other languages, or more complex scanning conditions.

The text fingerprint and the source anchor serve work identification and evidence verification, respectively, and the two should be validated separately. Users can recheck the source text on the basis of the anchors and record disputed judgments.

Future research can add samples with explicit revision records and different scanning qualities. For citation function, control sentences with multiple clauses and multiple citations should be added to measure the frequency of incorrect attribution.

## Data and Reproduction Notes

When reviewing the text fingerprint, evaluators need to fix the input files, the text extraction results, and the program version. If any one of these is changed, the corresponding file-pair determinations should be recorded separately.

When reviewing the source anchor, one can locate the sentence from the displayed page number and then locate the entry by its bibliographic key. The label name alone does not indicate whether the system has found the correct evidence.

The `qualifies` in the reproduction code stores the result of a single determination. For missed detections, the expected label, the actual determination, and the content similarity should all be retained so that subsequent independent verification is possible.
