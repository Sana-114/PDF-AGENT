## 2. 发现并修复的问题

### 题名检索遗漏预印本

原流程在 Semantic Scholar 失败后直接使用 Crossref，可能找不到没有被后者收录的论文。新增有界的 arXiv `ti:"完整题名"` 兜底，再使用 Crossref；不反复请求失败来源，不削弱指定修订版的验证规则。Atom 解析、429 和无效响应检查共用一个实现，避免三个入口的规则漂移。

查询语法参考 [arXiv 官方 API 手册](https://info.arxiv.org/help/api/user-manual.html)。保留外部限流告警，不能把兜底成功说成主来源无限额可用。

### 引用检索串与错误匹配

首次真实引用下钻把作者、题名和会议年份整串放入 arXiv 的标题查询，未找到 Adam。Crossref 随后返回另一篇随机优化论文，旧算法只检查候选自身的少数词，给出 0.60 并错误标为 matched。

修复采用保守的引号／作者句号分隔题名提取；格式不明确则保留原文，不编造题名。匹配新增双向标题覆盖：提取到题名时双方都必须覆盖；保留整串时用 Dice 重合度，减少短泛化题名的偏置。作者与年份仍独立检查，年份不同不能补造为一致。不是全体参考文献格式或身份精确率 100% 的证明。

### BGE 失败被静默降级

三个联网候选均出现一次 `WinError 10054`，但其余刷新仍成功。原流程捕获异常后用哈希向量返回推荐列表，不标注本次来源，容易误判为 BGE 全程成功。

现保存实际排序来源与降级警告，在推荐理由、API `ranking_provider`／`ranking_warning`、刷新摘要及后台任务结果中透传。使用已有 metadata 字段，无数据库表结构迁移。旧记录缺审计字段时返回空值，不追溯补造。降级后 feed 可以成功，**不再等同于语义模型成功**。

修复后真实复测恰好再次遇到降级：API 和任务明确标注 hash 及原因；随后任务调用恢复 BGE。原失败没有被后续成功覆盖。

## 5. 尚未关闭的门禁

1. 本机／最终部署 BGE 连接重置的根因和有限稳定性；不能靠不断重跑追绿，也不能把显式降级视为语义能力通过。
2. 多种引用版式、真正新论文到达后的增量窗口、长期 Beat 调度及外部 Worker、代码仓库检索补充、多用户隔离；本轮新 feed 中的直接 GitHub 链接及加分可见，但不证明仓库官方性或可复现性。
3. DPO 等完整跨文答案与最后同版稳定性、完整综述／写作／Future Work 科学质量、精细解析与资源边界仍按原记录未放行；本轮零 LLM 调用不改变它们的成绩。
4. 最终安装、干净启动、技术材料、实际 MP4、公网、体验账号、密钥轮换和正式发布仍未完成。

接下来应定位已记录的 BGE 连接问题并继续其余未通过功能的有限验收；不重做已完成的全库基础解析，也不将本轮三个通过样本扩大成六模块已验收。
